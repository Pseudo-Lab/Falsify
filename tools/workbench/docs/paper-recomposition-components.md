# 논문 재조판 부품 선정과 구현

2026-10-31 · 기준 커밋 `660552d` 이후 로컬 구현

논문을 문단·그림·표로 복원하고, 한 조판 규칙으로 편집본을 만드는 경로를 추가했다. 원본 배치 편집과 별도로 선택한다. 짧은 수정은 기존 원본 편집 경로를 계속 사용한다.

## 선택한 부품

| 부품 | 결정 | 맡기는 일 | 확인한 범위 |
| --- | --- | --- | --- |
| [DocVortex fork](https://github.com/Shinick-Han/DocVortex) | fork와 독립 변환 어댑터 작성 | 네이티브 PDF에서 구조·LaTeX·그림 자산 추출 | 0.6.9 실제 변환 및 오류 처리. 기본 웹 변환기로 채택하기에는 텍스트·서식 차이가 남음 |
| [TeXlyre BusyTeX](https://github.com/TeXlyre/texlyre-busytex) | 기존 1.4.1 재사용 | 브라우저 Worker에서 LuaHBTeX 컴파일 | 실제 TTF·OTF 문서와 작업대의 논문 전체 컴파일·다운로드 |
| fontspec·microtype | 수정 없이 패키지 재사용 | 글꼴 선택, 글자 돌출·폭 조정 | 같은 BusyTeX 배포의 런타임 부분을 별도 자산으로 구성 |
| 기존 PDF evidence·source session | 확장 | 원본 위치, 소스 편집, 변경 이력, 기준본 비교, BLUE 전달 | 기존 계약과 회귀 검사 유지 |

DocVortex의 기준 소스는 `a4f6e7a42268f1676b53d3640f45e21bf3cb1070`이다. 어댑터 실측은 해당 버전의 PyPI wheel로 수행했다. fork에서 직접 빌드한 바이너리와의 동일성은 확인하지 않았다. 실행법은 [변환 어댑터 안내](docvortex-adapter.md)에 있다.

Docling·Marker·MinerU는 이번 런타임에 추가하지 않았다. 선택한 변환기와 역할이 겹치며 모델·배포 의존성이 늘어난다. 별도 OCR 평가 프레임워크도 추가하지 않았다. 현재 필요한 검사는 앱의 원문 대조와 PDF 렌더링으로 수행한다.

## 구현한 경로

PDF 분석 → 문서 전체 조판 프로필 → 문단 흐름의 LaTeX → 브라우저 LuaLaTeX → 원본·기준본 비교 → 소스 편집 → PDF 다운로드.

고급 생성 옵션의 **문단 흐름으로 LaTeX 만들기**로 연다. 기존 **PDF를 LaTeX 소스로 편집**은 원본 쪽 배치를 기준으로 재구성한다. 새 경로에서는 원본 쪽마다 강제 페이지 나눔이나 긴 단 상자를 만들지 않는다.

프로필에는 용지 크기, 좌우 여백, 단 수, 단 간격, 본문 크기·줄간, 문단 들여쓰기와 역할별 서식을 기록한다. 원본에서 읽은 값과 기본값을 구분한다. 그림·설명의 연결 근거가 있는 인접 항목은 함께 배치하며, 래스터 안의 글을 다시 중복 출력하지 않는다.

새 경로는 Liberation Serif의 보통·굵게·기울임·굵은 기울임 네 글꼴을 프로젝트에 포함한다. 실제 원본 글꼴과 같은 서체라는 뜻은 아니다. 글꼴 파일과 추가 TeX 자산은 해시로 고정했다. fontspec·microtype 추가 자산은 약 0.44 MB이며 문서 내용은 외부 컴파일 서버로 보내지 않는다.

다운로드와 편집기는 같은 생성 PDF를 사용한다. 원본 PDF, 공격 없는 재구성 기준본, 편집본의 해시와 이력을 구분한다. 복원 진단은 화면·기록에 남기고 PDF에 공격 힌트를 추가하지 않는다.

## 실측에서 확인한 경계

7쪽 실제 논문이 6쪽의 문단 흐름 PDF로 생성되고 다운로드됐다. 글꼴은 PDF에 포함됐으며, 이어서 소스 편집기로 여는 동작도 확인했다. 제목·저자명 앞의 조판 명령이 다음 문단을 잘못 숨기던 소스 분석기도 수정했다.

이 결과는 전체 논문 복원 품질의 완료 판정이 아니다. 렌더링에서 첫 쪽의 전폭 제목·초록 구조, 일부 표의 행·열, 본문에 끼어든 머리말이 남았다. 글꼴 경고와 숫자 추출 차이도 관찰됐다. 추출문 대조는 그림 속 문자와 읽기 순서를 증명하지 않으므로 렌더링과 함께 확인한다.

DocVortex도 원본의 글꼴·용지·문단을 그대로 복원하지 않는다. 기본 출력은 XeLaTeX/ctexart이며, 현재 브라우저 Lua 프로필과 바로 호환되는 출력이 아니다. 독립 변환·비교 도구로 두고 기본 웹 경로에는 연결하지 않았다.

다음 품질 작업은 첫 쪽 전폭 영역, 표·수식·윗첨자의 구조 복원, 머리말·꼬리말의 본문 분리다. 검증 결과를 개선하려고 원문이나 의도한 RED 변경을 자동으로 고치지 않는다.

## 두 스킬을 적용한 기준

중복 변환기, 패키지별 fork, 별도 평가 플랫폼을 구현 목록에서 뺐다. 화면에는 방식 선택과 생성·편집·다운로드를 두고 상세 진단은 접었다. 글꼴 누락, 내용 차이, 생성 실패는 결과를 사용하는 데 필요한 정보로 유지했다. 논문과 하네스의 문장은 문체 교정 대상으로 삼지 않았다.

## 배치 스킬 fork 적용

[cosmo-agent-skills](https://github.com/Shinick-Han/cosmo-agent-skills)와 [ai4s-skills](https://github.com/Shinick-Han/ai4s-skills)를 fork했다. `paper-layout-review`의 검수 절차와 `paper-writer`의 그림·표 배치 관계를 프로젝트 전용 [falsify-paper-layout](../.agents/skills/falsify-paper-layout/SKILL.md)에 반영했다. 원문과 MIT 라이선스는 기준 커밋·해시와 함께 스킬 안에 보존했다. 배치 구현·검수 담당자는 AGENTS.md에서 이 스킬로 연결된다.

앱에서는 기존 PDF 기하 검사기를 재사용해 LaTeX 기준본의 겹침·잘림 지적을 Worker에서 수집한다. 결과는 출력 PDF 해시와 연결하고 비교 상세에 검사 범위를 남긴다. 결과가 다른 파일에 속하면 사용하지 않는다. 검사 결과로 다운로드를 막거나 PDF 안에 표시를 넣지 않는다.

문단 흐름 조판은 작은 그림을 단 폭까지 확대하던 처리를 바꿨다. 원본 표시 크기를 기준으로 가용 공간 안에서 비율을 유지하며, 두 단을 가로지르는 근거가 있는 그림·표는 전폭 float를 사용한다. 문단의 고립된 첫·마지막 줄을 줄이기 위한 TeX penalty도 적용했다.

스킬 구조 검사와 원문 해시 검증을 수행했고, 별도 작업자가 기존 PDF 전체를 렌더링해 검수 절차를 시험했다. 실제 논문의 새 출력도 브라우저에서 컴파일·다운로드했다. 표 구조, 글자 간격, 머리말 분리와 그림·설명 관계 복원은 계속 검증할 품질 항목이다. 기하 검사에서 지적이 없더라도 이 항목들이 통과했다는 뜻은 아니다.
