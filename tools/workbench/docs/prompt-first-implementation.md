# Prompt-first 구현 안내

RED와 BLUE는 독립적으로 파일과 자유 지시문을 받는다. 프롬프트 버전은 이름과 함께 저장·불러올 수 있다. 기본 복사 문구는 원본 PDF 첨부를 요청하며 추출문은 포함하지 않는다. 추출문과 선택한 Harness 지침 포함은 고급 옵션이다. 요청 지시문 기록은 실제 실행의 증명이 아니다.

외부 답변은 붙여넣거나 JSON·TXT·Markdown으로 가져온다. BLUE Markdown 결함 표는 행별 지적으로 읽고 뒤따르는 보고서를 별도로 보존한다. 원응답도 보존한다. RED의 불확실한 원문 위치는 후보를 미리보고 확인해 선택하며, 직접 연결도 가능하다. 직접 PDF 편집과 접힌 자동 실행·CLI·코드 harness 경로도 유지한다.

BLUE도 가장 가까운 원문 후보를 바로 확인해 연결한다. 나머지 후보와 직접 위치 선택은 접혀 있다. AI가 쓴 인용과 실제 연결한 원문은 따로 보존한다. 앱에서 프롬프트를 복사하지 않은 답변에는 앱의 기본 지시문을 요청 내용으로 기록하지 않는다.

## 확인한 동작

- 전체 앱 `npm test`, Cloud API 52개, 패키징 9개 검사 통과. 작업대 58개와 외부 작업대 13개 검사도 통과했다.
- Aside에서 기본 화면의 고급 설정이 닫힌 상태임을 확인했다. BLUE Markdown 표의 임의 유형·낮은 확신·위치 없는 지적·마지막 보고문을 가져와 기록했다. 유사 인용의 위치를 한 번 눌러 연결하고 AI 인용과 실제 원문이 각각 보존됨을 확인했다.
- 직접 문단 편집 후 RED에서 BLUE로 전달하는 합성 PDF 검사는 같은 출력 해시, 썸네일, 현재 입력과 모바일 배치를 확인했다. 모델 요청은 보내지 않았다.
- 실제 36쪽 PDF에서 원문 콘텐츠 스트림상 분리된 문장을 2쪽의 좌표 읽기 순서로 연결했다. 문단의 마지막 원본 그리기 위치를 보존해 흰색 마스크가 새 글자를 가리던 문제를 수정했다. 별도 PyMuPDF 렌더러에서 변경 문장 표시와 나머지 35쪽의 픽셀 동일성을 확인했다.
- 실제 브라우저에서 7,441,382바이트 수정본을 바로 다운로드하고 BLUE에 같은 SHA-256(`69117a042a1a93565eb39a27f1d8a2001a469bf44db624f939de2c797371d1e0`)의 파일을 전달했다. 입력 원본과 실험 산출물은 공개 소스에 포함하지 않았다.

## 남은 범위

이 36쪽 사례의 수정 페이지에서는 콘텐츠 스트림 순서로 전체 인용의 예상문을 계산하는 검사가 `expected_text_uncomputable`을 낸다. 파일과 미리보기는 사용할 수 있으며 검사 결과는 실패 상태 그대로 남는다. 수정 페이지의 일부 색상 직렬화 차이도 확인되어 그 페이지 전체가 픽셀 동일하다고 표시하지 않는다. 좌표 기반 예상문 검증과 다양한 겹침 레이어 사례는 후속 검사 대상이다.

그림·표의 구조화된 외부 응답 내보내기와 검색/Python 도구 자동화의 신규 구현은 후속 범위다. 외부 모델의 실제 탐지 성능은 이번 기능 검수와 별도 실험으로 평가한다.

Confluence 보관 API의 새 메타데이터 지원은 Worker `eb596314-6fe3-4544-ac9f-ba2dce4a6ba2`로 배포했고 configured=true를 확인했다. 합성 QA 기록은 팀에 공개하지 않았다.
