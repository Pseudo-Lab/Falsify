
The `layoutQuality` field is additive to `falsify.recomposition-check.v1`; the existing content and unavailable visual checks retain their meaning. It is diagnostic and never controls download. `inspectLayoutQuality({bytes, mupdf, profile})` can also score candidates directly. `score` is null because coverage is partial. `detectedIssuesScore` is 100 minus the sum of explicit issue penalties, floored at zero; it only compares detected defects under the same profile and is not a visual pass. Issue boxes are `[left, top, right, bottom]` in zero-origin MuPDF display points and page indices are zero-based. Each issue includes its evidence and penalty. The report is partial even with no findings.

Optional `layoutProfile.coordinateSpace` must be `output` to use caption asset or column page/box hints. `source` and unspecified coordinates are skipped, because repagination changes the output. The caller must supply independently mapped output hints; the checker still requires a unique actual caption and image match. A column requires `{pageIndex, bbox, anchorText}` where the exact anchor occurs uniquely on that page outside the column; this is a blank-column candidate, not proof of a column or vector-only occupancy.

`bodyLines: [{text}]` nominates body text: each line must match one actual output line uniquely before `bodyFontSize` is compared. No line-length heuristic classifies captions or references as body. Source `bodyFontNames` are descriptive only, never compared to fallback fonts. An independently resolved `outputBodyFontNames` list enables font-name comparisons for matched body lines. `headings: [{text}]` use unique actual matches. `coverage.profile` records checked and skipped nominations; absence of nominations is not coverage.

Painted text bounds can expose ink outside the page; axis-aligned rectangular clip paths can also expose clipped text paint bounds. Other clip operations remain unverified. Text paint operations supply overlap candidates, and image placements come from structured text. Small glyph touching, containment, complex writing directions, vector figures, arbitrary clipping, transparency, layers, occlusion and actual ownership are not completely verified. The PDF may omit clipped material from structured text. A zero penalty does not imply any unsupported condition passed. Geometry limits make the whole report unavailable, not a fabricated pass. No raster or external model is used. LayoutFlow was not copied: its object proposal metrics do not establish actual ink, style or caption ownership. Source models and existing MuPDF 1.28.1 APIs are reused.


Optional `flowExpectations: {floatingCaptionBlockIds: [id]}` allows a declared caption to move in extraction order. Each ID must identify one expected block and one `layoutProfile.captions` entry with the same normalized text and `coordinateSpace: "output"`. The caption must be uniquely observed alongside its actual image. Each caption occurs exactly once in both streams. After removing it, the ordered body must match, subject only to the existing one-way micro-sign and discretionary-soft-hyphen representations. Reported offsets identify caption-local or body-after-caption-removal scope. Missing or ambiguous evidence leaves flow unavailable. Without this option, ordered comparison is unchanged; movement locations remain unavailable when the full streams differ.

`coverage.clipping` is partial: MuPDF text-paint bounds are compared with active axis-aligned rectangle clips. Bounds are conservative and this is a candidate finding rather than glyph-level visibility proof. Non-rectangular paths, clip text, masks and other unsupported clips are counted and remain unverified. Image clipping alone is not a text defect. `captionObservations` exposes whether each declared caption and image was independently matched and spatially attached; it is not proof of arbitrary figure ownership.
