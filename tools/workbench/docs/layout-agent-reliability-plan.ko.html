완성 후의 사용 흐름

  1. 논문을 넣고 원하는 부분을 수정한다. 외부 AI 응답, 직접 편집, 연결한 AI 실행을 계속 지원한다.
  2. 필요하면 AI 레이아웃 조정을 시작한다. 재실행 중에도 이전 결과를 받을 수 있다.
  3. 결과 카드에서 현재 후보, 바뀐 페이지, 내용 대조 결과, 남은 배치 문제를 확인한다.
  4. 문제를 누르면 해당 쪽·영역을 연다. 원본과 후보를 비교하고 필요한 수정만 다시 요청한다.
  5. PDF를 받거나 BLUE로 보낸다. BLUE에는 화면에 표시한 후보 PDF와 동일한 바이트만 전달한다.
  6. 작업 저장을 선택하면 후보까지 함께 보관한다. 다시 열 때 이전 상태를 복구하고 사용자가 계속하기를 누른다.

기본 화면은 현재 단계에 맞는 주 동작을 강조한다. 결과가 생기면 PDF 받기를 강조하고, BLUE 검토는 선택 가능한 다음 동작으로 둔다. 소스 ZIP·실행 기록·전체 해시·세부 설정은 펼쳐서 확인한다.

기존 status·trace는 호환용으로 읽는다. 새 화면은 runState와 quality를 사용한다. 실행이 끝났어도 내용 차이나 겹침이 있으면 “작업 끝 · 확인할 곳 2개”로 표시한다. 전체를 확인하지 않은 결과에는 실제 관찰 범위를 표시한다.

내용 대조 기준은 AI 배치 시작 직전 PDF다. 사용자가 선택한 RED 변경도 이 기준에 들어 있다. 배치 작업은 그 변경과 나머지 내용을 유지한다. 지정한 그림 교체는 별도 허용 변경으로 기록해 예상 밖의 자산 손실과 구분한다.

추출 순서·Unicode·수식 때문에 판정할 수 없는 항목은 unverified로 남기고 확인한 근거를 보인다. 검사 수행 여부와 검사 결과를 서로 대신 사용하지 않는다.

후보와 소스를 한 쌍으로 보관한다

각 후보에는 소스 프로젝트, 그 소스로 생성한 PDF, 검사 결과, 출처와 체크포인트 ID를 연결한다. 미컴파일 소스는 “PDF 생성 전”으로 표시한다. 이전 후보 PDF를 현재 소스의 출력으로 붙이지 않는다.

재실행은 새 runId를 만들고 이전 후보를 유지한다. 새로 완성된 후보는 별도로 추가한다. 실패·취소·단계 한도에 도달해도 마지막 후보와 체크포인트를 선택할 수 있다.

저장은 기존 보관 정책을 따른다

기본 실행 상태는 메모리에 둔다. 기존의 “이 기기에 12시간 임시 저장”을 선택하면 후보와 체크포인트도 같은 만료 정책으로 저장한다. 큰 바이트는 IndexedDB에 두고 해시로 중복 제거한다. 만료·동의 해제 시 관련 데이터도 지운다.

기존 작업 JSON은 계속 불러올 수 있다. 큰 PDF·프로젝트는 기존 fflate로 작업 ZIP과 manifest를 묶는 경로를 추가한다. 저장 공간 부족을 알리고 작업 파일 받기를 제공하며, 화면의 현재 결과는 유지한다.

팀 영구 보관은 Confluence를 사용한다. 공개는 팀 전체 공개를 뜻하며 사용자가 선택한다. 원격 본문 한도를 따로 적용하고 큰 PDF를 JSON/base64 본문에 통째로 넣지 않는다. 첨부 경로의 실제 지원을 확인한 뒤 큰 작업 보관을 연결한다. 임시 저장과 팀 공개는 별개 동작이다.

중단된 모델 요청은 한 번만 실행한다

runId, stepId, 요청 지문과 접수 상태를 기록한다. 서버가 받은 동일 요청은 같은 결과를 반환한다. 재개는 확인된 마지막 도구 실행 이후부터 진행한다. 새로고침 뒤 접수된 요청은 상태 조회로 연결한다.

현재 레이아웃 step은 동기 POST라 조회 기능이 없다. 기존 RED/BLUE job의 식별·조회·취소·결과 보관 방식을 재사용한다. 브라우저 상태 복구와 모델 실행 재개는 각각 검증한다.

편집 대상을 계속 추적한다

기존 원본 노드 ID와 저장된 편집 계약은 유지한다. 레이아웃 세션에 stable targetId를 추가해 이전·현재 소스 범위를 연결한다. 편집 트랜잭션, 경로, 인접 구조와 내용 근거로 대상을 추적한다. 중복 문장과 구조 변경으로 여러 후보가 남으면 위치 후보를 보여준다.

숫자 누락·겹침이 남은 실행종료와 품질을 분리한다. 문제를 누르면 해당 쪽을 열고 PDF 받기는 유지한다.
이전 성공 → 재실행 → 초기 실패·취소이전 후보의 PDF 해시·소스·기록과 다운로드가 유지된다.
체크포인트 복원소스와 PDF가 같은 프로젝트를 가리킨다. 미컴파일 소스에는 이전 PDF를 현재 출력으로 표시하지 않는다.
새로고침·작업 파일 복구선택 후보·검사 결과·위치·체크포인트가 복구된다. 동의 해제·12시간 만료도 적용된다.
요청 접수 직후 새로고침동일 runId·stepId의 모델 실행은 한 번이다. 완료 결과를 조회해 다음 도구부터 이어간다.
A 문단 수정 후 B 조정이미 찾은 B를 전체 문서 재조회 없이 찾는다. 중복 위치·삭제·구조 이동도 검사한다.
페이지 수가 달라진 비교원본과 후보의 같은 내용으로 이동한다. 대응 없는 쪽은 각 쪽번호를 따로 선택한다.
빠른 쪽 전환 20회마지막 선택만 표시하고 이전 렌더는 취소한다. 같은 해시 문서 로드는 재사용한다. 같은 기기에서 변경 전후 시간·피크 메모리를 비교한다.
키보드·좁은 화면주 동작·쪽 이동·문제 이동을 키보드로 수행한다. 페이지 내용·진단의 텍스트 대안과 변화 알림을 제공한다. 데스크톱·390px에서 결과가 열린 상태를 확인한다.
실제 논문 출력기존 7쪽·36쪽 회귀 자료와 합성 표·그림을 사용한다. 작은 변경의 무관 영역, 긴 변경의 영향 페이지와 캡션을 비교한다. 선택한 RED 결함·숫자를 보존한다.
BLUE 전달선택 후보·미리보기·다운로드·BLUE 입력의 PDF 해시가 같다. RED 계획·정답·품질 힌트를 PDF나 BLUE 입력에 추가하지 않는다.
배포 일치소스·번들·설치본 버전과 해시를 대조한다. 재시작 전에 진행 작업 상태를 확인하고 결과·설정·논문을 보존한다.

코드·계약 검사를 먼저 실행한다. 다음에 브라우저에서 실패·복구·비교·다운로드를 검사하고, 마지막에 동의된 CLI 실행으로 전체 흐름을 확인한다. 새 실패가 없는 범위에서 검사를 반복하지 않는다.

적용 범위와 회귀 관리

첫 배포는 결과 상태, 후보 보존·복구, 대상 추적, 비교 화면과 미리보기다. 표 구조 확장은 별도 변경으로 검증한다. 기존 PDF 보존 편집과 독립 RED·BLUE·검수 동선을 유지한다. 작은 수정의 처리를 위해 자동으로 논문 전체를 재조판하지 않는다.

형상 충실도는 T-0157의 출력 기준으로 추적한다. 복구와 결과 활용 개선으로 전체 논문 복원 품질까지 완료 처리하지 않는다. 표 확장은 셀·구간별 지원 증거와 실제 조판 결과를 남긴다.

문구와 경고를 늘리는 방식으로 완료 기준을 대신하지 않는다. 문제 위치, 보존된 결과, 다음 동작을 구현한다. 두 글쓰기 스킬은 설명·명령 문장에 적용하고, 명령 식별자·스키마·논문 인용·수치·조건은 유지한다.

구현·검증은 WorkBite T-0152에 기록한다. 배포는 T-0073, 재구성 품질은 T-0157의 현재 문맥을 확인한 뒤 연결한다. 상태는 실제 수행 결과에 맞춰 갱신한다.
