# 계정 비밀번호와 세션

공유 기록 패널에 로그인한 활성 팀 멤버가 자기 비밀번호를 바꾸거나, 자기 세션을 모두 끝낼 수 있다. 화면은 `app/dist/cloud-records.js`가 계정 패널 안에 붙인다. `index.html`은 바꾸지 않는다. API 계약과 가짜 예시는 `cloud/api/PASSWORD-SESSIONS.md`에 있다.

## 비밀번호 변경

계정 패널의 **비밀번호 변경**에 현재 비밀번호, 새 비밀번호, 새 비밀번호 확인을 입력하고 버튼을 누른다. 확인이 다르거나 새 비밀번호가 12–128자가 아니면 서버로 보내지 않는다.

서버가 바꾸면 그 계정의 유효한 세션이 모두 끝난다. 이 브라우저는 토큰과 불러온 서버 기록을 지우고, 새 비밀번호로 다시 로그인해야 한다. 자동으로 로그인하지 않는다. 비밀번호는 요청 본문에만 있고 `localStorage`에 저장하지 않는다. 입력란은 요청 전에 비운다.

현재 비밀번호가 틀리면 `401 invalid_credentials`다. 해시와 세션은 그대로이고, 패널은 브라우저 토큰을 지우지 않는다. 세션이 만료·폐기된 `401 unauthorized`는 토큰을 지운다. 구서버가 경로를 모르면 `404`이며, 기록을 못 찾았다는 문구 대신 서버 업데이트가 필요하다고 알리고 토큰은 둔다. 비밀번호 변경 응답을 확인하지 못하면 같은 POST를 자동으로 다시 보내지 않는다. 해시 계산 중에 현재 세션이 폐기되면 배치는 비밀번호 행을 바꾸지 않는다.

## 모든 세션 끝내기

**모든 세션 끝내기**를 누른 뒤 **모든 세션 끝내기 확인**을 눌러야 요청이 나간다. 취소하면 아무 요청도 없다. 요청 본문은 없고, 지금 로그인한 세션의 토큰만 보낸다. 다른 계정의 세션, 공유 기록, 소유 권한, 멤버 자격은 바꾸지 않는다. 성공하면 이 브라우저의 토큰도 지운다.

**로그아웃**은 이전과 같다. 지금 이 세션만 끝낸다.

## 아직 정하지 않은 범위

계정 삭제, 기록 익명화, 비밀번호 복구, HttpOnly 쿠키 이전은 구현하지 않았다.

- 소프트 삭제는 `authors.deleted_at` 같은 새 마이그레이션, 세션 폐기, 로그인 거부가 필요하다. 기록은 같은 소유자 id로 남고, 공유 응답의 소유자 이름은 `authors`와 조인되므로 이름을 숨기려면 표시용 이름이 따로 필요하다.
- 하드 삭제는 `sessions`, `team_members`, `invitations.claimed_by`, `records`가 `authors`를 참조한다. 작성자를 지우면 공유 harness·실행·검수 소속이 끊긴다. 지금 스키마에는 cascade가 없다.
- 그 자리 익명화는 사용자 이름, 표시 이름, 비밀번호 해시를 바꾸고 세션을 폐기한 뒤 작성자 id를 유지하는 방법이다. 사용자 이름은 `UNIQUE`이고 `NOT NULL`이다. 이메일 열이 없어 검증된 다른 식별자에 이름을 옮겨 둘 수 없다.
- 복구는 현재 비밀번호 없이 비밀번호를 바꾸는 경로가 없다. `authors`에 이메일이나 다른 검증 채널이 없다. `scripts/invites.mjs`는 멤버 자격만 바꾸는 운영자용 SQL이다.
- 세션은 등록·로그인 JSON의 bearer 토큰이다. 페이지 출처와 API 출처가 다르므로 HttpOnly 쿠키는 상위 도메인 또는 같은 사이트 호스트, credentialed CORS, CSRF 방지, 클라이언트 변경이 필요하다.

이 항목은 제품 결정 전에는 구현하지 않는다.

## 로컬 시험

합성 계정만 쓴다. 운영 API는 호출하지 않는다. `cloud/api`에 `miniflare`와 `esbuild`가 없으면, 이미 설치된 `node_modules`를 `NODE_PATH`로 지정한다. 패키지를 새로 설치하지 않는다.

```text
node app/tests/account-password.spec.cjs
node app/tests/cloud-records-ui.spec.cjs
node --test cloud/api/test/password-sessions.test.mjs cloud/api/test/api.test.mjs
```

`app/scripts/test.mjs`의 파일 목록은 이번 변경 범위 밖이라 `account-password.spec.cjs`를 그 목록에 넣지 않았다. 위 명령으로 직접 실행한다.

비밀번호 변경은 기존과 같은 scrypt(`N=32768,r=8,p=3`)를 두 번 돈다. Worker `cpu_ms` 1000 제한은 이 Miniflare 시험이 적용하지 않는다. 배포 전에 프로덕션 CPU 여유를 확인한다.
