# Output profile adapter

`buildOutputProfile({bytes, mupdf, document, flow, expectedBlocks, fontPlan, selectedFamilyAliases, assetSpans})` returns `{profile, evidence}`. Pass `profile` as `layoutProfile` to `checkRecomposition` after compilation; preserve `evidence` separately so skipped checks are visible. `bytes` are the compiled PDF and `mupdf` is the already loaded module. `document` and `flow` are source-bound; `expectedBlocks` are the final edited block texts, including any flow fragments. The adapter does not read source rectangles as output coordinates.

A paragraph is nominated only when its complete normalized expected text is unique among expected blocks and appears as a unique sequence of output lines on one page. A line is passed to the checker only if its exact normalized text is unique across output pages. Missing, split-across-page, fragmented, reordered, ambiguous or differently represented text is skipped; no scientific symbols are normalized beyond whitespace. The checker independently reads glyph size and font names. Body size is a source-derived target; allowed output font names are explicit selected aliases or names parsed from the selected font bytes using `parseFont`. An unresolved font identity is unavailable, not an alias learned from output.

For each flow asset, `assetSpans` may nominate `{id, pageIndex, bbox}` in MuPDF output display coordinates (zero-based page); only a uniquely overlapping actual output image placement and unique complete output caption enable a checker nomination. A compiled point span alone does not establish an image bounding box. Vector paint is unsupported. Captions over 20 output lines are explicitly unavailable because the current checker has that limit. The checker also independently applies its own line-contiguity and image checks. Headings require unique single-line output. Columns are unavailable until independently supported output column bounds and an anchor outside each candidate are supplied. This is partial structured-text and image evidence, not a visibility or visual-quality pass.

Integration requires native flow to retain the final expected blocks and document/flow fragments, provide selected font bytes or verified aliases, and provide compiled output asset bounds where available. Call after final bytes are generated and before invoking `checkRecomposition`. Existing Typst block start/end metadata are not asserted as image bounds; they need a validated coordinate conversion and extent. No compositor or checker wiring is included in this worker's scope.
