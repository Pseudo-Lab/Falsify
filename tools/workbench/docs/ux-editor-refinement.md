# 직접 편집 UX 개선

2026-10-27 · Workbench 0.2.0-alpha.17

PDF의 문단이나 변경 항목을 누르면 같은 편집창에서 내용을 고칩니다. `After 수정` 버튼은 제거했습니다. 데스크톱에서는 원문 옆에 편집창이 나타나고, 작은 화면에서는 원문 아래로 이어집니다. 생성본은 편집창을 닫은 뒤 비교할 수 있습니다.

## 바뀐 동작

- 변경 항목을 누르면 저장된 수정 내용으로 다시 열립니다.
- `이 쪽의 문단 선택`을 펼치면 드래그 없이 문단을 선택할 수 있습니다. 문단 버튼은 키보드로도 사용할 수 있습니다.
- 다른 위치를 선택할 때 작성 중인 내용이 있으면 편집창에 적용·닫기 안내를 표시합니다.
- 문단을 준비하는 동안 진행 상태를 표시합니다. 같은 원본의 같은 쪽은 분석 결과를 재사용하고, 다른 파일로 바꾸면 새로 분석합니다.
- 파일을 넣기 전의 빈 편집 도구는 숨깁니다. 초안 보관, 파일 정보, 외부 AI 응답 입력은 펼쳐서 사용합니다.
- RED와 BLUE 실행 버튼에 역할 이름을 표시합니다. 연결이 필요하면 해당 위치에서 PC 연결 패널을 열 수 있습니다.
- BLUE 실패 안내는 한 곳에 표시합니다. RED에도 접수 상태 조회를 제공합니다. 조회는 기존 요청의 상태를 읽습니다.

## 글쓰기 원칙을 기능에 적용한 기준

| 검토한 요소 | 결정 | 이유 |
| --- | --- | --- |
| 별도 `After 수정` 버튼과 재입력 경로 | 변경 항목 선택으로 통합 | 같은 변경을 두 경로로 찾을 필요가 없음 |
| 중복된 실패 문단 | 상태 한 곳과 복구 버튼으로 정리 | 원인과 다음 행동을 함께 찾을 수 있음 |
| 항상 노출되던 좌표·발생 순번 | 편집창에서는 쪽과 선택 구간만 표시 | 정확한 위치는 변경 기록에 보존됨 |
| 원문 인용·파일·요청 식별자 확인 | 유지 | 다른 구간이나 다른 실행 결과의 혼입을 막음 |
| 모델 실행과 팀 공개 동의 | 유지 | 실제 전송 및 공개 범위를 사용자가 선택함 |
| 미확인 요청 자동 재전송 금지 | 유지 | 중복 실행과 비용 발생을 막음 |
| 작성 중인 내용의 보호·실행 취소 | 유지 | 입력 내용과 원본을 복구할 수 있어야 함 |

`avoid-ai-writing`과 `anti-defensive-writing`은 설명을 줄이는 데 적용했습니다. 한국어 문장은 문맥에 맞게 검토했습니다. 기능 변경은 코드와 동작 검증으로 판단합니다.

## 조사와 재사용 결정

상호작용, 복구, 접근성 관점의 에이전트 검토와 공개 문서를 참고했습니다. 사람 대상 사용성 조사를 수행한 결과는 아닙니다.

- [NN/g의 직접 조작 원칙](https://www.nngroup.com/articles/direct-manipulation/): 대상과 작업을 가까이 둔다는 방향을 참고했습니다.
- [W3C의 키보드 접근성 설명](https://www.w3.org/WAI/WCAG21/Understanding/keyboard.html): 문단 선택에 키보드 경로를 추가했습니다.
- [W3C의 포커스 가림 설명](https://w3c.github.io/wcag/understanding/focus-not-obscured-minimum.html): 문서를 가리는 고정 팝업을 일반 배치로 바꿨습니다.
- [W3C의 폼 레이블 안내](https://www.w3.org/WAI/tutorials/forms/labels/): 전송 동의의 의미를 툴팁에만 넣지 않고 화면에 유지했습니다.
- [PDF.js](https://github.com/mozilla/pdf.js/)와 [ProseMirror](https://prosemirror.net/)를 비교했습니다. 현재 PDF.js 뷰어와 원문 위치에 연결된 편집 세션을 확장했습니다. 새 편집기를 추가하거나 PDF 전체를 문서 모델로 변환하는 의존성은 도입하지 않았습니다.

편집 엔진은 alpha.16의 지원 범위를 유지합니다. 실제 생성본과 검증 상태를 확인하고 과학적 타당성은 검수에서 평가합니다.
