# PDF 문단 편집 보정 — alpha.32

외부 제안으로 텍스트를 늘리거나 줄인 뒤, 변경하지 않은 내용과 인용번호가 함께 보존되도록 수정했다.

- 글꼴의 ToUnicode에 같은 문자가 두 번 정의돼 있을 때, 인코딩으로 왕복 확인되는 코드의 폭을 사용한다. 소문자 `l`을 다른 글리프 폭으로 계산하던 문제가 여기에 해당한다.
- 스타일이 바뀌는 경계의 공백을 원문 좌표와 변경 범위로 확인해 복구한다. 사용자가 작성한 After는 고치지 않는다.
- 양쪽 본문 조각 사이에 놓인 위첨자 인용번호를 같은 줄에 포함한다. 다른 단의 텍스트 때문에 처리 순서가 갈려도 인용번호의 자리와 폭을 함께 계산한다. 원래 작은 글자 크기와 높이를 유지한다.
- 저장 순서가 달라지면 글자 좌표로 페이지 전체 내용을 대조한다. 모든 추출 문자의 인덱스를 계산에 포함하며, 원문으로 입증된 줄끝 하이픈과 단어 경계를 유지하는 줄바꿈만 정규화한다. 문구 누락·단어 합침·단어 순서 변경·알 수 없는 제어문자는 통과시키지 않는다.

이 대조는 PDF에 공백을 기록한 바이트가 동일하다는 뜻이 아니다. 문단을 재배치하면서 단어 사이 공백이 실제 줄바꿈으로 바뀌는 것은 허용한다. 글자 겹침, 원래 단 경계, 머리말·꼬리말 검사는 별도로 유지한다.

회귀 검사는 중복 글꼴 매핑, 기존 인코딩 글리프 보존, CID 글꼴, 위첨자와 인접 단, 스타일 경계 공백, 내용 누락과 공백 손실을 포함한다. 개인 논문은 테스트 데이터나 공개 배포에 넣지 않는다.

엔진 패치는 `app/src/paragraph-vendor/patches/`에 있고 런타임과 빌드 출처 해시는 `runtime/candidate-manifest.json`에 기록한다.
