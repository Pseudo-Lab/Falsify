# Paper workspace implementation contract

Preserve the airport visual system and independent RED/BLUE/review/harness routes. Source PDF and last generated PDF remain downloadable. No automatic model run or team publication. Private drafts are explicit opt-in, expire after 12h and can be deleted. Confluence is the only permanent remote store. Sources, edits and diagnostic/gold metadata must never be forwarded to BLUE together: BLUE gets the selected PDF only.

## Shared browser APIs (classic UMD globals; no framework replacement)

### `FalsifyPaperEdits` — edit-core owner

`create({fileHash,name,segments,now?,id?})` returns a session with `snapshot()`, `add(edit)`, `update(id,changes)`, `remove(id)`, `setEnabled(id,bool)`, `undo()`, `redo()`, `subscribe(fn)` (returns unsubscribe). Changes emit a defensive snapshot. Snapshot has `schema:'falsify.paper-edits.v1',fileHash,name,revision,edits,canUndo,canRedo`. `segments` have `{id,label,text,pageIndex?}`. Add fields: `{pageIndex,segmentId?,before,after,anchor?,origin}`. Anchor is `{bbox?:[x0,y0,x1,y1],occurrence?:integer,start?:integer,end?:integer}` in PDF page coordinates, and may carry bounded style hints. Origin is `human`, `external-ai-import` or `ai-proposal`. Return the new edit ID. Stored edit includes stable ID, enabled, first/original Before, current After, anchor, origin, createdAt/updatedAt and bounded revision history. Original source remains immutable. Numeric/citation changes are allowed for human/imported attacks; do not inherit legacy AI-only restrictions. `draft({snapshot,now})` / `restoreDraft(envelope,{fileHash,now})` validate TTL/hash/limits. Do not persist automatically; UI owns explicit opt-in browser storage. No tokens/source PDF bytes in draft metadata.

### `FalsifyExternalRed` — external-import owner

`buildPrompt({segments,fileHash})` -> string with stable IDs, page labels and recommended `{changes:[{segmentId,pageIndex,before,after}]}` response. `parse(text,{segments,fileHash})` -> `{proposals,diagnostics}`. Proposal includes edit fields plus `status:'matched'|'ambiguous'|'missing'`, `matches:[{segmentId,pageIndex,start,end}]`. Only exact unique verified match is matched; no first-occurrence/fuzzy guess. Support fenced JSON, legacy candidate objects, explicit Before/After pairs and unified diff with recoverable exact context. Unknown/incomplete/malformed text is diagnosed, never interpreted as executable HTML/code. No eval/network/model. Optional full rewritten text may produce bounded diff candidates, not presumed scientific success.

### `FalsifyBrowserPdf` — browser-export owner

`async prepare({file,edits,signal})` -> `{file:File,sha256,verification,pageMap,warnings}`. The output File must be real PDF bytes, not a simulated HTML view. Edits use enabled objects above. Verification truthfully records applied/unapplied/unknown and quality warnings, never stamps success after failure. Bounds, source hash and stale/abort checks required. Reuse an existing OSS content editor/runtime, with pinned source/license manifest; avoid rasterizing all pages, white overlays leaving original text, annotation-only or silent source fallback as an alleged edit. If an operation cannot generate a file throw an actionable typed error; UI retains the original/last generated PDF. Unsupported font/layout features must be disclosed. Browser offline execution must require no companion/API/upload. Only this owner changes app/package*.json and export-specific build/vendor files.

### `FalsifyPaperWorkspace` — UI owner

`acceptProposals(proposals,{origin='external-ai-import',model?}={})` shows proposals for explicit acceptance; never applies ambiguous targets. `getSource()` -> `{file,fileHash,segments}` or null. Dispatch `falsify:paper-workspace-ready` when exposed and `falsify:paper-workspace-source` when source changes. Import UI owner mounts its own small section in workspace using these public APIs. Viewer observes real `#paper-file` input immediately, not just extraction success, so image/scanned PDF can still be displayed. Existing AI `applyResponse` feeds validated proposals through workspace adapter without running models again. Manual provenance must not be fabricated as model/harness execution.

Integration addition (same frozen edit schema): workspace also exposes `getEditSnapshot()` -> current defensive edit snapshot or null, `getOutput()` -> `{file,sha256,verification,revision}` for the last real generated PDF or null. Dispatch `falsify:paper-workspace-edits` with snapshot after edits, and `falsify:paper-workspace-output` with hash/revision/verification (no PDF bytes) after generation. A team-publication button dispatches `falsify:paper-team-share`; the separate manual-records adapter opens an explicit consent UI, never auto uploads. A BLUE handoff dispatches only the PDF via existing falsify:blue-file, never edit metadata. Manual-review/archive owner alone handles manual provenance records; no fake AI harness/run/attestation.

UI owner alone edits index.html, document-red.js, visual-workflow.js and workspace CSS/controller. It includes edit-core/external-red/browser-pdf/import UI scripts in valid order and preserves legacy routes and consent. Exported file must be the exact previewed file/revision; stale revision remains downloadable only as explicitly last-generated, never latest. Separate current PDF download and explicit Confluence team-publication action. Undo/redo and change-list navigate original pages. Before/after canvases reuse PDF.js with text/selection overlay; inline editor delegates to session. No forced giant multi-page scroll.
