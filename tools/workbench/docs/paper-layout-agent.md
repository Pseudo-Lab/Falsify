# AI가 배치를 다듬는 PDF 편집

AI가 현재 LaTeX 소스와 PDF 페이지를 보고 배치 도구를 선택한다. 기존 PDF 편집·컴파일·렌더링·검사 기능을 사용하며, 원문과 사용자가 선택한 RED 변경을 유지한다.

## 사용 순서

1. 논문 PDF에서 LaTeX 기준본을 만든 뒤 편집하거나, 원래 LaTeX 소스를 연다.
2. 사용할 변경을 선택한다. PC의 Codex CLI에 로그인하고 companion을 연결한다.
3. 고급 AI 배치 항목에서 원하는 배치를 적고 시작한다.
4. AI가 원본 PDF의 글·좌표·페이지 이미지와 생성본을 대조하고 배치 도구를 실행한다. 재구성 소스에서는 제목·저자·초록을 전폭으로, 본문을 단으로 나누거나 기존 블록을 머리말·꼬리말로 옮길 수 있다.
5. 후보 PDF를 확인하고 다운로드한다. BLUE에 보낼 때는 이 PDF만 전달한다.

## 결과 확인과 이어서 작업하기

결과에는 실행 상태, 내용 대조, 배치 검사와 실제 AI에 전달한 페이지 수가 따로 표시된다. 문제 항목을 누르면 해당 쪽으로 이동한다. 원본과 후보의 쪽번호를 각각 고르거나 **같은 내용으로 이동**으로 대응하는 쪽을 찾는다. 페이지 텍스트도 펼쳐 읽을 수 있다.

**후보 PDF 다운로드**는 현재 후보를 바로 받는다. **이 PDF로 BLUE 검토**에는 같은 PDF 바이트만 전달하며, 공격 근거와 레이아웃 기록은 포함하지 않는다. 소스 ZIP·전체 해시·실행 기록은 **작업 파일·기록**에 있다.

기본 상태는 현재 탭에 보관한다. **이 기기에 12시간 임시 저장**을 선택하면 후보와 체크포인트를 포함한 소스 작업을 IndexedDB에 저장한다. 작업 파일로 내보내 다른 탭에서 불러올 수도 있다. 복구는 저장된 결과만 열며, AI를 다시 호출하지 않는다. 이어서 실행하려면 시작 버튼을 누른다.

새 companion은 단계별 접수 영수증을 반환한다. 접수 여부가 불분명한 요청은 저장된 ID로 조회하며 자동으로 다시 보내지 않는다. 서버 재시작·보관 만료로 이전 요청을 찾지 못하면 대기 요청을 정리하고 사용자가 후속 실행을 선택한다. 구버전 companion은 기존 동기 호출을 사용한다.

기본 PDF 편집은 계속 사용할 수 있다. AI 실행은 시작 버튼으로 요청하며 기존 Codex 구독을 사용한다. API 키를 등록하는 과정은 추가하지 않는다.

## 역할과 기록

블록 편집·표·그림·글꼴·후보 저장 도구를 포함한 현재 23개 명령과 입력 형식은 [도구 계약](paper-layout-tools.md)에 정리했다. 아래 목록은 처음 연결한 기본 명령이다.

모델은 다음 도구와 인자를 선택한다. 앱은 도구를 실행하고 결과를 돌려준다. 배치 스킬은 프로젝트 전용 `falsify-paper-layout`이며 companion에도 동일한 파일을 포함한다.

| 도구 | 실행 내용 |
| --- | --- |
| `read_source` | 프로젝트의 LaTeX 소스를 읽는다. |
| `replace_source` | 배치 명령을 수정하고 내용 보존 여부를 확인한다. |
| `compile_pdf` | 현재 프로젝트를 기존 브라우저 컴파일러로 생성한다. |
| `inspect_pdf` | 생성한 PDF의 겹침·잘림 등을 검사한다. |
| `render_pages` | 요청한 쪽을 PNG로 렌더링해 모델에 제공한다. |
| `read_reference` | 원본 PDF의 페이지 텍스트·좌표·영역 ID를 읽는다. |
| `render_reference_pages` | 원본 페이지를 PNG로 제공한다. 생성본 이미지와 구분해서 전달한다. |
| `restructure_source` | 현재 블록의 내용을 유지하며 전폭 영역·본문 순서·머리말·꼬리말 배치를 바꾼다. |
| `finish` | 현재 결과와 남은 사항을 반환한다. |

기록에는 실제 실행한 도구, 소스·PDF 식별자, 원본과 생성본의 검사·렌더링 범위가 남는다. 배치 수정은 논문의 과학적 주장·수치·인용이나 의도적으로 넣은 결함을 바꾸지 않는다. 모델이 내용 변경을 제안하면 해당 도구 실행을 거절하고 이유를 돌려준다.

원본 PDF는 브라우저에서 실제 바이트의 해시를 확인한 뒤 텍스트·좌표와 페이지 이미지로 읽어 모델에 제공한다. 원본 이미지와 생성본 이미지는 각각 `original`, `candidate`로 표시한다. 원본을 읽고 이미지를 관측한 실행만 원본 대조 흐름을 완료할 수 있다.

구조 변경은 기존 내용 블록을 모두 한 번씩 유지한다. 원본에서 반복되는 동일한 머리말은 페이지 템플릿으로 사용하며 이를 출력하려고 빈 쪽을 추가하지 않는다. 글자·그림을 새로 만드는 내용 변경은 이 도구의 역할에 포함하지 않는다.

검사·렌더링 완료 여부는 최근 대화 내용과 별도로 유지한다. AI가 앞선 도구 결과를 더 이상 보지 못해 같은 검사를 반복하는 문제를 줄인다. 구조 편집 후의 위치 정보와 원본에서 읽은 최초 위치 정보도 구분한다.

실제 7쪽 논문에서 원본 1쪽과 후보 1쪽을 비교한 뒤 각주를 하단으로 옮기는 실행을 확인했다. 146개 내용 블록과 그림·글꼴 파일은 유지됐고 브라우저 출력도 7쪽이었다. 첫 쪽 왼쪽 단의 각주가 본문 영역에 들어오면 그 단에 공간을 예약한다. 다른 쪽·오른쪽 단·전폭 각주의 일반적인 공간 예약과 표 셀 복원은 이 검사 범위에 포함하지 않았다. 해당 문서에는 표 구조, 일부 단어 경계·기호와 4쪽 겹침 개선이 남아 있다.

## 실행 범위

현재 구현은 앱 도구 호출을 모델이 선택하는 방식이다. 기존 CLI의 임의 셸·파일 실행은 켜지 않는다. 각 모델 요청은 한 번만 전송하며 도구 반복 횟수에 한도가 있다. 중단하면 후속 요청과 결과 반영을 멈춘다. 이미 접수된 단일 CLI 호출은 서버에서 끝날 수 있다.

배치 검사는 관측한 범위만 보고한다. 컴파일 성공, 기하 검사, 모델의 시각 검토를 구분한다. 검사가 일부이거나 개선할 곳이 남아도 생성된 PDF를 받을 수 있다. 후보와 현재 편집본은 구분해 보관한다.

원본 PDF를 LaTeX로 복원하는 과정에서 표 구조나 캡션 연결이 유실된 경우에는 복원 단계 개선이 필요하다. 배치 에이전트의 완료 상태를 원논문 복원 완료로 해석하지 않는다.
