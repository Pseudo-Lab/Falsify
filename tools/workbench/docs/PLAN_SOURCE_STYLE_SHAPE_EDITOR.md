## 1. 완성할 사용 흐름

PDF에서 그래프를 누르면 해당 그래프 안에서 바로 편집한다.
- 곡선의 원하는 부분을 위/아래로 당겨 봉우리·골을 만든다.
- 중앙 손잡이로 위치·높이를 바꾸고 양옆 손잡이로 적용 폭을 조절한다.
- 작업 중 바로 미리보며, 되돌리기·다시하기·원본 비교·PDF 받기를 사용한다.
- 좌표표·상세 모양·축 변경은 접힌 고급 기능에 둔다.
- OCR·축 보정·추출 방식·원시 JSON·상세 진단은 에이전트 API/MCP와 작업 정보에 둔다.
- 표를 선택하면 셀 입력, 막대를 선택하면 끝점 이동, 그림을 선택하면 해당 요소 편집만 나타낸다.
모양 조절 때문에 다른 화면으로 이동하거나 분석/생성 버튼을 반복해서 누르게 하지 않는다.

기본 축·눈금·서체·범례·페이지 배치는 원본을 사용한다. 값을 바꾸지 않으면 원본 bytes를 그대로 반환한다.

원본 PDF의 축·글꼴·라벨 객체를 그대로 남길 수 있는 경우에는 해당 요소를 추출·재생성하지 않는다.

## 3. OSS 조합 결정

- 조작부 1순위: AUX ChartHandle/Range의 필요한 모듈. 전체 Equalizer/오디오 화면은 가져오지 않는다.
- 모양 계산: MIT ml-peak-shape-generator v5.6.0, commit 5a87af23408aedf00e35e43ca6648a20cf6455bd.
- DSSSP는 drag/width UX를 실제 확인한 대안이다. 현재 vanilla JS 앱에 React를 새로 넣지 않는다.
- Paper.js는 기본 의존성으로 추가하지 않는다. 기존 경로 코드만으로 hit-test/편집 연결을 충족하지 못한다는 재현 근거가 있을 때 필요한 부분만 도입한다.
- Fityk 전체 앱과 피팅 엔진, Mystique/Chart2SVG는 이번 기본 경로에 넣지 않는다.

첫 실증에서 AUX의 실제 필요 모듈과 이벤트 수명주기를 확인하고 source SHA·파일별 해시·라이선스를 고정한다.

## 4. 데이터·장면·명령을 분리한다

### 원본에 묶인 장면
sourceFileHash, graphId, sceneRevision, pageIndex, page bbox, plot bbox, axis transform, series/branch IDs, 원본 경로/샘플, style, 원본 사용 위치/페인트 식별을 보관한다.
원본 장면은 변경하지 않고 그 위에 명령 이력을 적용한다.
직접 편집으로 생긴 중간 PDF를 매번 재분석하지 않는다. 현재 시각 편집 세션의 기준 bytes와 명령 이력을 유지한다.
외부 편집으로 PDF가 바뀌었을 때만 새 장면을 준비한다.
벡터 추출의 MuPDF seqno만으로 PDF content-stream operator 위치를 같다고 가정하지 않는다. QPDF 토큰/행렬/clip/스타일을 함께 대조해 바인딩을 검증한다.

### 공통 편집 명령
단일 falsify.chart-edit-plan.v1 계약에 prepare된 장면 ID/revision, source hash, 대상 series/branch, 순서가 있는 operations를 둔다.
최소 동작:
- deform: 선택 범위를 부드럽게 밀기. 위로는 bump/peak, 아래로는 well.
- move: 선택한 모양을 좌우/상하 이동.
- resize: 선택한 모양의 좌/우 폭과 높이 조절.
- set-values: 고급 좌표 수정.
undo/redo는 같은 명령 이력의 커서를 이동한다. 원본에 누적해서 다시 계산하므로 드래그 횟수에 따른 오차가 쌓이지 않는다.
명령 ID·이전 revision으로 중복 적용/오래된 결과 게시를 방지한다. 기존 세대 번호·요청 취소 패턴을 재사용한다.

Gaussian 등의 프로파일은 국소 변경량/영향 곡선 계산에 사용한다.
선택 범위 밖은 변경량 0이 되도록 경계 연결을 적용한다. 무한 꼬리를 가진 Gaussian 단순 덧셈이나 원본 전체 재피팅으로 범위 밖 데이터를 바꾸지 않는다.
원래의 잡음·오차막대·다른 계열을 자동으로 평활화하거나 재해석하지 않는다.
불규칙한 peak를 이동/넓힐 때는 원본 모양의 잔차를 포함한 좌표 변형을 사용한다. 전체를 이상적 Gaussian으로 대체하지 않는다.
분기/루프는 branch/path parameter로 지정하며 x 하나에 y 하나라고 강제하지 않는다.
선형/로그 축은 원본 변환으로 왕복한다. 기본 조작에서 축 범위가 자동으로 늘어나지 않으며, 축 변경은 명시적 고급 편집이다.
의미가 연결된 평균·오차막대는 연결이 확인된 그룹 단위로 편집할 수 있게 한다. 곡선 샘플을 평균/CI로 추정해 자동 이동하지 않는다.

### 같은 계산 코드 사용
공통 코어는 DOM 없는 JS 모듈로 작성한다.
브라우저 worker와 기존 MiniRacer runtime이 같은 고정 bundle을 실행한다. Python에 별도의 변형 알고리즘을 다시 작성하지 않는다.
손잡이는 입력 파라미터만 만들고, PDF 출력기는 계산 결과와 원본 장면을 받는다.

## 5. 원본 서식 보존 출력

### 벡터 PDF
1. 기존 추출 결과에 선택 경로의 실제 paint occurrence 바인딩을 추가한다.
2. 선택한 paint만 수정하며 원본의 행렬·clip·색·선 굵기·dash·cap/join·opacity·페인트 순서를 유지한다.
3. 공유 Form이면 선택된 호출 경로만 복제한다. 다른 페이지/다른 사용 위치는 변경하지 않는다.
4. 축·눈금·격자·범례·글꼴·라벨은 원본 객체를 그대로 남긴다.
5. 기존 image occurrence 수술과 새 vector 수술이 공통으로 쓰는 토큰 유틸만 좁게 추출한다. 검증된 기존 이미지 편집기를 전면 재작성하지 않는다.
기존 원본 스트로크를 그대로 두고 새 곡선만 덧그리거나, 곡선 bbox를 흰 사각형으로 지워 주변 격자를 없애는 방식은 사용하지 않는다.

### 래스터 그래프
1. 원본 크롭과 곡선의 픽셀 마스크/색·굵기를 재사용한다.
2. 선택 곡선을 분리한 배경을 한 번 준비하고, 변형한 곡선만 같은 해상도·원본 plot 좌표에 합성한다.
3. 격자·문자·다른 계열과 겹친 부분은 보호 마스크와 기존 이미지 처리 도구로 분리·복원한다.
4. 이미지가 PDF에 독립 사용 위치로 있으면 기존 occurrence 교체 경로를 우선하고, 합성 영역이면 기존 region export에 연결한다.
5. 원본 크롭 전체를 기본 Chart.js 테마로 새로 그리지 않는다.
래스터에서 가려졌던 배경을 원본 bytes 그대로 복원할 수 있다고 가정하지 않는다. 복원 구간은 기록하고 원본 비교에서 드러낸다.
같은 색 교차·격자 겹침은 이 경로의 핵심 검증 사례다. 복원 성공을 확인하지 않은 상태를 서식 보존 완료로 표시하지 않는다.

### 표와 일반 피규어
기존 표 셀 입력은 유지하되 원본 기준선·정렬·글자 크기·테두리 보존을 검증한다. 숫자 수정에서 기본 글자 축소가 필요 없는 경로를 우선한다.
막대는 상단/끝점 드래그로 편집한다. 산점은 선택한 점을 이동한다.
일반 사진/개념도에 곡선용 숫자 변형을 적용하지 않는다. 기존 이미지 교체/라벨 편집을 대상 선택 시에만 표시한다.
이 작업에 사진 생성 모델이나 전체 표 인식 엔진 재개발을 포함하지 않는다.

## 6. 미리보기와 성능

장면 준비는 처음 선택할 때 한 번 수행한다. PDF/OCR/분석 결과는 원본 hash와 영역에 묶어 재사용한다.
드래그 중에는 브라우저에서 원본 배경 위 선택 곡선만 갱신한다. 매 pointermove마다 OCR·PDF 생성·서버 호출을 하지 않는다.
requestAnimationFrame으로 마지막 입력만 반영하고 공통 코어는 worker에서 실행한다.
드래그 종료 시 확정 명령을 기록한다. PDF 미리보기는 debounce하고 최신 revision만 게시한다.
다운로드 버튼은 현재 revision의 PDF를 생성해 바로 받는다. 이전 생성본을 현재 편집으로 오인하게 하지 않는다.
BLUE 전달은 기존 onOutput/file handoff를 사용해 같은 확정 PDF bytes를 넘긴다.
성능 목표는 일반 합성 1,000점 계열에서 드래그 프레임 p95 33ms 이내다. 구현 후 실측해 기록하며 현재 성능으로 주장하지 않는다.
source/scene 교체, 새 편집, undo, 닫기, 도구 전환 때 진행 중 작업을 취소한다.

## 7. API/MCP

기존 read-only paper MCP는 BLUE 분석용으로 유지한다.
RED 편집용 도구는 별도 server/tool group으로 제공하고 공통 코어·장면·출력 서비스를 호출한다.
필요한 도구는 prepare_chart_edit, preview_chart_edit, export_chart_edit 세 개다. 변형 종류마다 별도 MCP 도구를 늘리지 않고 operations 계약을 사용한다.
새 API는 장면 준비/미리보기만 추가하고 최종 출력은 기존 visual export 서비스에 새 plan kind 또는 버전 계약으로 연결한다. 기존 v1 요청을 다른 의미로 해석하지 않는다.
사람·에이전트 작성 출처는 호출 경로에서 지정한다. 기존 author:'human' 고정값이 에이전트 편집에도 붙지 않게 기록 어댑터를 확장한다.
모델명·설정은 실제 실행 정보가 있을 때만 기록한다. BLUE에는 PDF만 전달하며 변경 마스크/공격 힌트는 넣지 않는다.

| 통합 조율자 전용 | server.py, paper-visual-edit-ui.js, paper-visual-integration.js, entry HTML, 공용 build/release 목록 | 각 작업 계약 충족 후 | 기존 텍스트·표·RED/BLUE 경로 회귀 검사 |

공용 대형 파일을 여러 작업자에게 동시에 배정하지 않는다. 새 모듈로 병렬 구현한 뒤 조율자만 entry/server/기존 통합 파일을 연결한다.
작업 완료 보고만으로 통합하지 않고 실행 증거와 patch를 검토한다.

## 9. 실행 순서

### Gate 0 — 원본 보존 가능성 먼저 확인
실제 production 진입점으로 native 단일 곡선과 raster 단일 곡선의 no-op 및 국소 이동 사본을 만든다.
가장 큰 불확실성은 선택 곡선의 제거/교체와 래스터 배경이다. 이 결과로 소유 경계를 확정한 뒤 UI 전체 연결에 들어간다.
UI를 먼저 완성하고 또 다른 기본 테마 출력으로 끝내지 않는다.

### Wave 1 — 세 갈래
P1 계산, P2 벡터, P3 UI를 병렬 진행한다. UI는 P0 fixture로 개발하며 백엔드를 기다리지 않는다.
조율자는 P7 fixture·독립 검사와 P4의 래스터 실증을 진행한다.
계산 코어가 끝난 좌석은 P5 API/MCP로, 벡터 좌석은 P4 확대/교차 사례로, UI 좌석은 P6 대상별 단순화로 이어간다.
사용 가능한 좌석이 더 있으면 P4와 P7을 별도로 배정하되 소유 파일은 유지한다.

### Wave 2 — 같은 편집을 끝까지 연결
원본 선택→드래그→자동 미리보기→즉시 다운로드→BLUE를 하나로 연결한다.
UI의 중복 분석/생성 버튼과 기본 좌표표를 정리한다.
native/raster 출력·표/그림 기존 편집·작성 출처·취소/undo를 같은 실제 흐름으로 확인한다.

### Wave 3 — 회귀 확인 후 배포
최종 단위/통합/브라우저 검사와 Windows·macOS ARM/Intel CI를 수행한다.
공개 ZIP에 필요한 vendor 소스·license·hash·runtime을 포함한다.
공개 웹·설치본·공식 Falsify branch는 별도 사용자 배포 요청 또는 해당 작업에 포함된 명시적 배포 범위에 따라 같은 commit으로 반영한다.
이번 요청은 계획 작성이므로 배포를 시작하지 않는다.

## 10. 완료 기준과 검사 경계

- 수정 없는 export는 원본 bytes/SHA 그대로이며 페이지 수/크기/회전도 같다.
- 선택 범위 밖의 데이터는 exact 동일. Undo는 원본 상태와 동일하다.
- 변형한 경로의 원본 스타일·clip·레이어 순서를 유지한다. 비선택 page/영역은 동일 렌더러/DPI에서 비교한다.
- 렌더 AA 차이는 고정 fixture와 대조해 경계에서만 허용하고, 격자/문자 손실을 허용치로 숨기지 않는다.
- native line/cubic, 계단형, 비대칭 봉우리·골, log 축, 다중계열, 공유 Form, 회전/잘림, 오차막대·교차를 검사한다.
- 기존 13개 그래프 추출 fixture를 재사용하고 출력/편집 사례를 추가한다. 모든 검사를 새로 만드는 작업으로 확장하지 않는다.
- 사람 UI와 API/MCP가 같은 plan/revision에서 같은 geometry를 만들고, 다운로드와 BLUE 입력 SHA가 같다.
- 수정 중 포커스/선택이 유지되고 느린 과거 미리보기가 최신 편집을 덮어쓰지 않는다.
- 기본 화면에 좌표표/알고리즘 선택/원시 JSON을 열지 않고도 대표 그래프 변경을 완료한다.
- 표 숫자·기존 그림 교체·텍스트 편집·마지막 생성본 다운로드·Confluence 기록의 기존 경로가 유지된다.
- 실논문 원본·정답지·실험 응답은 공개 fixture나 저장소에 넣지 않는다.
- PDF 내부에 변경 위치/훈련 힌트/진단 문구를 추가하지 않는다.

출력 생성 실패와 진단 경고를 구분한다. 생성된 후보는 실제 상태와 함께 받을 수 있게 유지하며, 마지막 생성본과 원본도 계속 받을 수 있게 한다.
파일이 만들어지지 않았을 때만 현재 후보 생성 실패로 표시한다. 실패를 숨기거나 오래된 PDF를 최신 수정본처럼 건네지 않는다.

## 11. 가장 큰 위험과 줄이는 방법

1. native 추출 경로와 실제 PDF paint 바인딩: 기존 seqno를 stream index로 간주하지 않고 Gate 0에서 토큰 단위로 대조한다.
2. raster 교차 부분의 배경 복원: 처음부터 독립 실증을 진행하고 원본 마스크 밖 보존과 교차 구간을 별도로 검사한다. 이미지 생성 모델로 전체 그림을 대체하지 않는다.
3. UI/API 계산 차이: 하나의 DOM 없는 JS 코어를 브라우저·MiniRacer에서 실행한다.
4. 기능 증가: UI 소유자는 기본 흐름의 버튼을 추가하기보다 기존 좌표/분석 패널을 고급/도구 경로로 옮긴다.
5. 회귀·작업 충돌: 기존 경로를 동작 어댑터로 유지하고 공용 파일 통합은 조율자 단독으로 처리한다.

이 계획의 가장 빠른 경로는 새 범용 그래프 편집기와 글꼴/축 재생성기를 만드는 것이 아니라, 원본의 고정 요소를 남기고 변하는 곡선/값만 편집하는 경로를 연결하는 것이다.



## 12. 실행 결과

기본 진입점은 기존 **표·그래프·그림 고치기 → 그림 또는 페이지 영역 선택 → 그래프 고치기**다. 곡선 모양 조절, 막대 끝점·산점 이동, 비교·되돌리기·직접 다운로드와 RED MCP를 연결했다. 원본 페이지의 모든 그래프를 자동 검출해 클릭 대상으로 만드는 기능은 이번 진입점에 포함하지 않는다.

원본 native line/cubic과 한 단계 공유 Form, RGB/ICC·soft-mask 래스터, 최상위 filled 직사각 막대·원형 산점이 검증 범위다. 래스터 검은 곡선의 자동 분리와 Form 내부 mark, 패턴 채움은 기존 고급 도구 범위로 남긴다. 상세 사용법은 [그래프 편집](paper-chart-shape.md)에 있다.

Python 전체922개 검사 중915통과·환경별 제외7·실패0. Node 전체 및 마지막 UI·패키징 검사가 통과했다. 실제 Aside native/막대 다운로드·undo 원본 일치·BLUE PDF 해시 일치, 실제 공개 논문17쪽의 영역 밖 보존을 확인했다. 실행 근거는 소스 밖 shape-implementation에 보관한다. 배포와 원격 CI는 별도 실행 단계다.
