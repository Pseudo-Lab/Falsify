# Workbench 0.2.0-alpha.36

PDF 편집과 LaTeX 입력에서 재현한 결함을 수정했습니다.

- 윗첨자 숫자를 바꾸거나 앞뒤에 숫자를 추가할 때 원래 서식을 유지합니다.
- 문단 모델과 페이지 추출 순서가 다른 경우, 원문 위치와 전체 페이지 문자 대응으로 숫자 변경을 검사합니다. 문자 누락·중복·순서 변경과 다른 Unicode 문자는 실패로 남깁니다.
- 링크가 있는 숫자를 늘리면 원래 목적지를 유지하며 새 숫자 전체를 클릭할 수 있습니다. 이웃 링크·다른 글자와 겹치는 확장은 적용하지 않습니다.
- 그대로인 링크와 그림 링크, 문서 열기 동작을 실제 글자·화면·PDF 객체 그래프와 대조합니다. PDFium의 생성 표시는 확인한 조건에서만 구분합니다.
- LaTeX ZIP의 상대 경로와 `graphicspath`를 시작 파일의 작업 디렉터리와 입력 순서에 맞춰 분석합니다.
- 실험용 PDF 재구성에서 두 단의 경계 판정, 세로 간격과 꼬리말 앞의 본문 공간을 수정했습니다.
- 악센트 문자와 `µ`/`μ`를 추출해도 원래 Unicode가 유지되도록 했습니다. 시험한 실제 문서의 화면은 이 변경 전후가 같았습니다.

실제 7쪽 PDF의 숫자 편집에서는 모든 페이지의 텍스트 검사가 통과했고 링크 검사 실패가 없었습니다. 나머지 6쪽의 렌더링은 원본과 같았으며, 바꾼 번호의 링크 영역만 새 숫자 길이에 맞춰 넓어졌습니다.

PDF→LaTeX 재구성은 계속 실험 기능입니다. 실제 36쪽 문서는 현재 37쪽으로 재구성됩니다. 12·20쪽의 두 단이 한 단으로 쌓이던 문제는 수정했지만, 원본 Harding 글꼴과 대체 글꼴의 폭 차이 때문에 5쪽의 긴 그림 설명이 다음 쪽으로 이어집니다. 원본과 같은 줄·글꼴 배치, 수식과 숫자의 전체 충실도 검증은 남아 있습니다. 기본 PDF 보존 편집 경로와 구분해 사용하세요.
