# 팀원 초대와 공동 기록

## 이용자: 처음 가입하기

1. 운영자에게 개별 초대코드를 비공개로 받습니다. 초대는 기본 7일 안에 한 번만 사용할 수 있습니다.
2. 웹앱의 **결과 기록 → 공유 기록 → 로그인·초대 가입**에서 사용자 이름, 비밀번호, 초대코드로 가입합니다.
3. 다음부터는 아이디·비밀번호로 로그인합니다. 초대코드는 다시 필요하지 않습니다.
4. 로컬 항목 하나를 골라 실제 전송 내용을 확인하고 올립니다. 기본은 비공개이며, 공유는 로그인한 팀원 전원에게 보입니다.

GitHub Pages의 정적 화면과 소스는 공개입니다. 공동 API는 초대받은 활성 회원의 세션으로만 읽고 쓸 수 있습니다.
저장소 초대 권한과 연동하는 기능이 아니며, 웹페이지 자체를 비공개 호스팅으로 바꾼 것도 아닙니다.
CLI 로그인·companion 페어링과 공동 기록 로그인은 별개입니다. API 키나 페어링 토큰을 가입 폼에 넣지 마세요.
초대코드는 URL·저장소·공개 채팅에 올리지 않습니다. 브라우저는 가입 시도 뒤 입력값을 지우고 서버는 코드 해시만 저장합니다.

## 운영자: 초대 발급

이 명령은 저장소의 `cloud/api`에서, 해당 Cloudflare 계정의 D1 쓰기 권한으로 실행합니다.
`npm ci --ignore-scripts`로 잠금 파일의 CLI를 설치한 뒤 사용하세요. 운영 권한을 팀원에게 나눠줄 필요는 없습니다.

```powershell
node scripts/invites.mjs issue --env production --out C:/Users/user/Downloads/falsify-invite-person1.txt
```

생성된 파일 내용만 해당 사람에게 비공개로 전달합니다. 파일은 저장소 밖의 새 절대 경로여야 하며 기존 파일은 덮어쓰지 않습니다.
표준 출력에는 코드가 나오지 않습니다. 유효기간을 줄이려면 `--hours 24`처럼 1–168시간을 지정합니다.
검증 환경은 `--env staging`입니다. 명령에 환경을 반드시 지정하고 공유 초대코드 하나를 여러 사람에게 배포하지 마세요.

## 기존 계정 승인·팀원 권한 해제

초대 도입 전 계정은 자동으로 회원이 되지 않습니다. 실제 사용자를 확인한 운영자만 승인합니다.

```powershell
node scripts/invites.mjs admit --env production --username existing_user
node scripts/invites.mjs revoke --env production --username former_member
```

`changes: 0`은 대상이 없거나 바꿀 내용이 없다는 뜻일 수 있으므로 성공으로 단정하지 마세요.
권한 해제는 회원 자격과 기존 세션을 무효화하지만 기록을 삭제하지는 않습니다. 이미 받은 사본이나 로컬 편집기 내용은 회수할 수 없습니다.
일회용 초대코드는 소지자를 인증하는 것이므로 유출 시 다른 사람이 먼저 사용할 수 있습니다. 본인 확인은 전달 과정에서 운영자가 맡습니다.
비밀번호 재설정·변경·계정 삭제와 전체 세션 관리 UI는 아직 지원하지 않습니다.
