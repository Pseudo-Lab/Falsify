# Falsify 외부 AI RED BLUE 작업 흐름 North Star

기준일: 2026-10-28 · 스펙 v1 · 상태: alpha.29 프롬프트 중심 흐름 구현·검수 완료. 배포 결과는 WorkBite T-0152 참조

적용 대상: 사용자가 지정한 Falsify 프로젝트 orchestrator. 다른 Codex agent·하위 작업자·검수자에게는 이 문서의 열람·준수 의무가 없다. 해당 orchestrator가 필요한 내용만 개별 작업 지시로 추려 전달한다.

## 목표

사용자는 원하는 외부 AI와 프롬프트로 논문을 검토하고, 받은 답변을 Falsify에 가져와 RED 수정 PDF 또는 BLUE 검토 기록을 만든다. PC 연결·API 등록·JSON 직접 수정 없이 이 흐름을 끝낼 수 있어야 한다. RED와 BLUE는 각각 독립적으로 사용한다.

사용 성공의 기준은 서로 다른 AI의 답변을 누적하고, 원하는 변경을 체크해 자연스러운 PDF로 받은 뒤, 그 파일의 BLUE 검토 결과도 가져와 기록하는 것이다. 앱에서 요청을 만들지 않고 외부에서 먼저 작업한 답변도 받는다.

이 문서는 Falsify orchestrator가 이번 웹앱 개발을 판단·조율하는 기준이다. Falsify 팀의 공식 연구 목표나 연구용 harness의 성능을 정의하지 않는다. 구현 진행도와 검증 결과는 WorkBite T-0152 및 커밋·검사 결과에 남긴다. 계획을 구현 완료로 표시하지 않는다.

구현·검증 증거: [prompt-first-implementation.md](prompt-first-implementation.md), 이전 alpha.28 [구현 기록](external-ai-implementation.md). 배포 결과는 WorkBite T-0152의 체크포인트로 확인한다.

## 2026-10-28 후속 결정: 프롬프트 중심 기본 사용

기본 하네스는 자유 지시문이며 논문 PDF와 함께 외부 AI에 제공한다. 기본 지시문 복사에 원문 전체 추출문을 강제로 포함하지 않는다. 도구 실행·CLI·모델·예산·JSON 설정은 접힌 고급 기능이며 일반 사용은 펼치지 않고 완료한다. 지시문 저장·불러오기와 기존 팀 하네스의 지시문 재사용을 지원한다. 검색/Python 그림 생성 자동화의 신규 구현과 완전한 논문 분해 내보내기는 후속이다.

원문은 좌표 읽기 순서와 문맥으로 후보를 찾고 근접 후보를 PDF 위에서 확인받는다. 가장 가까운 후보 하나를 먼저 보이고 필요할 때 나머지를 펼친다. 사용자 선택 전에는 유사 위치를 자동 적용하지 않는다. 원문·변경문·위치·원응답은 앱이 보존한다.

BLUE는 진행자 예시처럼 Markdown 결함 표와 마지막 대조 방법 설명을 그대로 가져온다. 임의 유형, 세 단계 심각도, 낮은 확신, 확인필요를 보존하며 위치가 없어도 기록한다. PDF 내부 검토 지시와 실제 도구 사용 여부를 구분해 기록한다. 새 wave 소유권과 API는 [prompt-first-contract.md](prompt-first-contract.md)에 정의한다.

## 확정된 사용자 결정

| 결정 | 구현 기준 |
| --- | --- |
| Q1 답변 형식 | 권장 JSON을 제공하고 설명문·코드블록·명시적인 Before/After 답변도 받는다. 사용자가 JSON을 직접 고치게 하지 않는다. |
| Q2 외부 AI 자유도 | 사용자가 AI·프롬프트·harness·첨부 자료를 선택한다. 앱의 프롬프트 조립·원문 복사는 선택 기능이다. |
| Q3 RED 범위 | 제목·본문·수치·조건·인용 등 편집 가능한 텍스트 전체를 수정할 수 있다. 그림 교체·표 구조 변경은 후속 과제다. |
| Q4 공격 조합 | 공격 유형 복수 선택. 선택한 유형의 개별·복합 공격을 모두 허용한다. 모든 후보에 모든 유형을 강제로 넣지 않는다. |
| Q5 위치 없는 결과 | 지적·제안을 보존하고 위치를 나중에 연결한다. BLUE는 위치 없이 기록 가능하다. RED는 위치가 연결되고 선택된 변경부터 적용한다. |
| Q6 답변 누적 | 새 답변은 기본 추가. 체크박스로 반영·제외한다. 체크 해제해도 제안과 출처를 보존한다. |
| Q7 자동 갱신 | 체크·편집 후 PDF 미리보기를 자동 갱신한다. 입력 반응을 유지하고 불필요한 생성·렌더링을 줄인다. |
| Q8 겹치는 수정 | 원문 범위가 겹치는 수정안은 하나만 선택한다. 새 대안을 선택하면 기존 선택이 풀린다. 합치려면 사용자가 별도 수정안을 작성한다. |

공격 유형의 현재 명시적 모순·조건 누락·근거 없는 해석을 복수 선택으로 바꾼다. 유형을 난이도와 동일시하지 않는다. 외부 답변에 유형이 없어도 가져오며, 기존 L1~L3 기록은 호환해 읽는다.

## 사용 흐름

RED: 논문 입력 → 선택적으로 요청 복사 → 외부 답변 가져오기 → 변경 목록에서 선택·수정 → 자동 미리보기 → PDF 다운로드.

BLUE: 검토할 논문 입력 → 선택적으로 요청 복사 → 외부 답변 가져오기 → 지적·근거 확인 → 결과 기록. 사람 평가는 별도 검수에서 진행한다.

외부 답변 입력은 붙여넣기와 JSON·TXT·Markdown 파일을 지원한다. 붙여넣으면 해석 결과를 표시하고, 정상 항목을 사용하면서 불명확한 항목만 보완한다. 여러 답변을 합치더라도 원응답은 답변별로 보존한다.

RED에서 BLUE로 이동할 때는 클릭 시점의 선택·편집을 반영한 PDF를 준비한다. BLUE 모델 요청에는 그 PDF에서 얻은 입력만 포함하고 RED 계획·원본 비교·공격 근거·사람 판정은 넣지 않는다. 전달은 BLUE 자동 실행을 뜻하지 않는다.

## 최소 인터페이스 계약

아래는 구현자가 고정할 의미 계약이다. 정확한 필드·직렬화·이벤트 명칭은 0단계에서 하나의 기술 계약으로 확정한다. 사용자에게 이 내부 필드를 입력시키지 않는다.

| 데이터 | 책임과 보존 규칙 |
| --- | --- |
| 문서 식별 | 앱이 원본 파일·추출문 해시와 버전을 관리한다. 답변에 해시가 없어도 현재 문서에 가져올 수 있다. 명시적인 다른 문서 식별이 있으면 연결 대상으로 표시해 확인한다. |
| 응답 묶음 | 답변 ID, RED/BLUE 역할, 원응답, 가져온 시각, 선택적인 모델·프롬프트·harness 정보. 외부 작업에 없는 정보를 앱이 생성해 실행 사실처럼 기록하지 않는다. |
| 제안 항목 | 안정적인 ID, 변경 또는 지적, 근거, 출처 응답 ID, 선택 여부, 위치 상태. RED는 before/after, BLUE는 지적 인용·설명을 사용한다. |
| 위치 | 앱이 문단 ID·원문 범위·페이지·좌표를 연결한다. 줄바꿈·공백·PDF 하이픈 정규화는 원문으로 역매핑할 수 있어야 한다. 여러 위치 중 첫 번째를 임의 선택하지 않는다. |
| 선택·충돌 | 제안 보관과 실제 반영을 분리한다. 동일 위치·동일 변경은 출처를 보존해 묶는다. 다른 대안은 함께 표시한다. 충돌 선택 교체는 원자적으로 처리한다. |
| 직접 합친 안 | 새로운 수정안으로 보관하며 바탕이 된 제안들을 연결한다. AI 원응답을 덮어쓰지 않는다. |
| 생성 입력 | 원본 파일, 활성 편집, 글꼴·내보내기 설정을 식별하는 생성 키. undo/redo로 되돌아갈 수 있는 revision 번호 하나만으로 동일성을 판단하지 않는다. |
| 생성 출력 | 실제 PDF File, 해시, 생성 키, 페이지 연결 정보, 적용 내역. 화면·다운로드·BLUE 전달이 같은 출력에 연결된다. |

권장 응답은 schema·requestId·role·status와 RED changes 또는 BLUE findings를 사용한다. 앱이 요청을 만든 경우 ID를 자동 대조한다. 앱에서 요청을 만들지 않은 답변에는 ID를 새로 타이핑하게 하지 않는다.

RED의 before/after와 근거 인용은 논문 언어를 유지한다. 설명은 한국어 기본값을 제공한다. after가 빈 문자열이면 삭제로 처리한다. uncertainty·모델명·도구 사용 정보는 필수 입력으로 두지 않는다. 자료 부족이 판정에 영향을 주면 해당 항목에 표시한다.

일반 문장의 해석으로 확정할 수 없는 변경은 원응답과 함께 보존해 위치·수정 내용을 직접 보완하게 한다. 가져오기 과정에서 원래 답의 의미를 바꾸거나 근거를 만들어 채우지 않는다. 외부 문헌 인용은 문서 내부 인용과 분리해 보관한다.

## 자동 갱신과 출력 품질

체크·타이핑·선택 표시는 즉시 반영한다. 입력 반응 100ms 이내를 목표로 측정하며, 이는 현재 측정 결과가 아니다. PDF 생성 완료 시간과 구분한다.

연속 입력은 묶어서 생성하고 생성 작업은 동시에 쌓지 않는다. 새 편집이 오면 이전 작업을 취소하거나 그 결과를 폐기한다. 작업 완료 시 생성 키를 대조해 오래된 출력이 최신 화면을 덮어쓰지 못하게 한다.

원본 분석과 같은 생성본의 PDF 문서·페이지 렌더링을 재사용한다. 변경 페이지를 우선 표시한다. 엔진이 전체 파일 생성을 요구하는 경로는 전체 생성을 사용하되 중복 실행과 렌더링을 줄인다.

생성 중에도 입력창·포커스·커서·한국어 조합 상태를 유지한다. 미리보기 갱신 때문에 편집기를 재생성하지 않는다. 마지막 미리보기에 갱신 상태를 표시한다.

다운로드 클릭 시 미확정 편집을 포함한 현재 의도를 고정한다. 해당 생성본이 준비되면 바로 다운로드한다. 생성 실패나 이전 생성본을 최신 파일로 가장하지 않는다. 기존 원본·마지막 생성본은 식별해서 받을 수 있다.

변경은 필요한 원문 범위에 우선 적용한다. 짧은 수정 때문에 전체 논문을 재조판하지 않는다. 페이지 외형·비선택 내용 보존과 현재 36쪽 사례의 성과를 유지한다. 변경 하이라이트는 화면 비교용이며 BLUE PDF에 앱의 정답·공격 표식을 새로 삽입하지 않는다.

## 기록과 복구

원응답·누적 제안·체크 상태·위치 연결·직접 편집과 생성본의 관계를 함께 기록한다. 같은 응답의 체크 변경·내보내기는 새 AI 실행으로 세지 않는다. 외부 모델·도구 사용은 제공된 정보만 기록한다.

Confluence는 유일한 영구 원격 보관소이며 팀 공개 저장은 사용자가 실행한다. 작업 중 복구는 기존 로컬 초안 동의와 12시간 임시 보관 범위에서 확장한다. 입력 중인 편집도 복구에 포함하고 기존 로컬 기록은 보존한다. Confluence에서 불러온 기록은 자동으로 영구 로컬 복사하지 않는다.

반복되는 실행 미검증·과학적 타당성 안내는 기록 상세에 모은다. 주 화면에는 반영할 변경, 연결할 위치, 다음 행동을 표시한다. 형식 오류 하나로 정상 항목 사용까지 막지 않는다.

### 파일 소유권

| 담당 | 소유 파일 |

`paper-workspace.js`는 B만 수정한다. C는 독립 모듈로 생성/캐시 API를 제공하고 B가 연결한다. A는 작업대 공개 API로 연결한다. 신규 공용 파일의 정확한 경로는 S0에서 지정한다. 다른 소유자의 파일 변경이 필요하면 해당 소유자 또는 조율자에게 요청한다. 소유권 이전은 기록하고 이전 작업자의 쓰기를 끝낸 뒤 진행한다.

기존 `docs/paper-workspace-contract.md` 등의 오래된 소유권 표와 동작 제한이 이 계획과 다르면 orchestrator가 S0 계약과 개별 작업 지시에 차이를 반영한다. 다른 agent에게 이 문서의 우선 적용을 요구하지 않는다. 기존 저장 형식 호환은 유지한다.

## 작업 시작과 인수인계 규칙

1. 사용자가 지정한 Falsify 프로젝트 orchestrator만 작업 시작·재개 시 이 문서를 먼저 읽고 계획·선행 계약·배정 경계를 확인한다.
2. orchestrator는 작업자에게 필요한 스펙, 정확한 시작 SHA, 수정 가능한 파일, 완료 검사만 개별 전달한다. 전체 North Star 열람을 요구하지 않는다.
3. 다른 Codex agent·하위 작업자·검수자는 개별 작업 지시를 따른다. 이 문서에서 다른 과제·모델 설정·전역 소유권을 상속받지 않는다.
4. 사용자 후속 결정이 스펙을 바꾸면 orchestrator가 이 문서와 영향받는 개별 작업 지시를 갱신한다.
5. orchestrator는 실제 진행·검사·커밋·남은 결함을 WorkBite T-0152에 기록한다. 작업자는 별도 배정이 없으면 담당 조율자에게 결과를 반환한다.
6. orchestrator는 체크박스·위치 매칭·출력 문제가 사용자의 다음 행동을 해결하도록 검수한다. 반복 경고나 일괄 차단으로 완료 기준을 대신하지 않는다.
