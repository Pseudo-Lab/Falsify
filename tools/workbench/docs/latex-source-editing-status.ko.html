LaTeX 편집 구현 상태

2026-10-31 · 버전 0.2.0-alpha.36. 공개 웹·설치본에 배포하는 기능과 지원 범위입니다.

빠른 사용법

  1. RED의 파일 입력에 .tex 또는 그림·참고문헌·스타일 파일을 포함한 .zip을 넣습니다.
  2. 원본 미리보기에서 고칠 곳을 누르거나, 외부 AI의 Before/After 응답을 가져옵니다.
  3. PDF 다운로드로 현재 변경본을 받습니다. BLUE로 보내기는 같은 PDF만 넘깁니다.
  4. 작업을 이어 하려면 작업 JSON 저장을 누릅니다. 새 화면의 첫 파일 입력에 그 JSON을 넣으면 복구됩니다. PDF 만들기를 눌러 다시 시작합니다.

실제 컴파일고정한 BusyTeX 1.4.1의 pdflatex/BibTeX8과 texlive-basic. 별도 서버에 논문을 업로드하지 않고 브라우저 Worker에서 실행

파일과 기록현재 PDF 다운로드, 동일 파일의 BLUE 전달, 원본 ZIP/작업 JSON, 12시간 임시 저장 선택, 기존 기록 형식에 소스 출처 연결
기준본 보존비교한 재구성 PDF의 바이트를 그대로 편집기에 인계. 원본·무공격 기준본·RED 변경본의 해시와 계보를 분리

PDF만 있을 때

alpha.36은 단 분류·꼬리말 겹침과 일부 문자 추출을 수정했습니다. 실제 36쪽 사례는 글꼴 폭 차이로 37쪽이며, 원본 배치와 수식·숫자의 전체 충실도 검증은 진행 중입니다.

기존 PDF 편집이 기본입니다. 고급 생성 옵션 → PDF를 LaTeX 소스로 편집 (실험)에서 재구성을 선택할 수 있습니다. 원본과 공격 없는 재구성본을 비교하고, 필요한 곳을 보정한 뒤 편집 기준본으로 선택합니다. 생성 PDF와 LaTeX ZIP은 이 화면에서 받을 수 있습니다.

이 경로는 원래 TeX 파일을 되찾는 기능이 아닙니다. 현재 단순 본문·그림 crop·일부 괘선 표를 편집용 소스로 구성합니다. 복잡한 다단 문서, 수식·첨자·각주·인용의 의미와 원본 배치는 아직 복원 품질을 개선해야 합니다. 추출 단어·숫자의 일치만으로 조판이 같다고 판정하지 않습니다.

검사한 것과 남은 확인

합성 소스의 실제 Windows Aside 브라우저 컴파일, 혼합 서식 변경, 다운로드와 BLUE 파일 해시 일치, 작업 JSON 복구를 확인했습니다. 기본 각주·hyperref 인용 표기 override와 원래 카운터·링크도 검사했습니다. 변경 하이라이트는 화면 레이어이며 생성 PDF에 넣지 않습니다.

XeLaTeX/LuaLaTeX, natbib/biblatex 및 사용자 정의 매크로, 실제 사용자 템플릿, 새 경로의 macOS/Safari 실증, 실제 Confluence 게시·불러오기는 남아 있습니다. Linux 브라우저 CI는 기존 소스 경로 검사를 통과했습니다. 최초 소스 컴파일에는 약 128MB의 고정 자산을 내려받습니다. 합성 문서 성능을 실제 논문 성능으로 해석하지 않습니다.
