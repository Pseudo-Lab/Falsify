# Changed source complexity ratchet

Run `npm ci --prefix tools/quality --ignore-scripts`, then `node tools/quality/check.mjs <base-commit-sha>`. The check compares committed `HEAD` with that commit in `app/src` and `app/local` for JavaScript and Python files. It parses JavaScript with the pinned dev-only Babel parser and Python with the standard library AST. No runtime bundle depends on the parser. Parse failures fail the check and identify the path.

Each function starts at one; branches, loops, exception handlers, conditional expressions and boolean operators add decisions. Switch cases and Python comprehensions/match cases count as decisions. Nested functions are counted separately. This is a practical approximation, not a claim about whole-repository debt or an interchangeable measure with other CCN tools. Function identity uses lexical names and occurrence order; renames are treated as new functions. An unchanged historic function is retained. A changed function may remain above 50 only if it does not increase its prior score; a new function must stay at or below 50. If an exceptional increase is necessary, add a reviewed entry to `exceptions.json` keyed by path and function ID with a specific `reason` and numeric `ceiling`. This is tracked in version control and does not waive future increases beyond the ceiling.

The Pages check uses the push's previous commit, or the first parent on manual runs. It needs complete Git history; it does not certify other platforms or detect uncommitted changes. `node --test tools/quality/complexity.test.mjs` covers regex literals, nested functions and threshold behavior.
