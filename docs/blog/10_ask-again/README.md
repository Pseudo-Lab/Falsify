# 같은 질문 여러 번 묻기 — 흔들리는 판정과 새는 정보 막기

![cover](cover.png)

> 작성: 이건규 · 게시: 2026-11-02 · 가짜연구소 Falsify 자료 탭


## 이 글은 AI로 초안을 작성하고 사람이 검토했습니다!

어제 '맞음'이라던 AI가 오늘은 같은 질문에 '아님'이라고 답한 적이 있나요?

Falsify에서 같은 입력을 같은 모델에 두 번씩 넣어 봤습니다. 세 대상 중 두 번의 판정이 일치한 것은 하나뿐이었습니다. 한 모델을 10번 반복했을 때도 결과가 하나로 모이지 않았습니다.

이번 글은 두 가지를 다룹니다.

1. **흔들림**: 한 번의 판정을 믿지 않고, 흔들리는 정도 자체를 기록하는 방법
2. **새는 정보**: 검색이나 메모리처럼 측정에 몰래 끼어드는 정보를 막는 방법

이번에도 새 채팅과 기록표만으로 실습합니다.

> 이 글의 Falsify 수치는 김가경 님의 「탐지기를 측정한 4주와 빌런나이트 발표」(2026.10.29)에서 가져왔습니다. 작은 규모의 관찰이므로 특정 모델의 일반적인 일치율로 읽지 마세요.

## 1. 같은 입력에 왜 다른 답이 나오나요?

생성형 AI는 같은 입력에도 매번 조금씩 다른 답을 만들 수 있습니다. 이런 성질을 **비결정성**이라고 부릅니다.

채팅 제품에서는 이유가 더 많아집니다.

| 흔들림의 출처 | 예시 |
|---|---|
| 답을 만드는 방식 | 같은 질문에도 다음 단어를 고르는 과정이 매번 다를 수 있음 |
| 제품 설정 | 추론 수준, 모델 선택, 기능 업데이트 |
| 대화 상태 | 같은 채팅을 이어 쓰면 앞의 대화가 영향을 줌 |
| 메모리·개인화 | 다른 대화에서 저장된 내용이 새 채팅에 들어옴 |
| 도구 | 검색 결과가 그때그때 달라짐 |

채팅 화면에서는 이 중 많은 것을 직접 보거나 바꿀 수 없습니다. 그래서 원인을 찾기보다 먼저 **흔들린다는 사실을 기록하는 것**에서 시작합니다.

## 2. 사람과 프롬프트에 따라서도 달라집니다

Falsify에서는 같은 변조본을 여러 참가자가 각자 AI로 검토했습니다. 지적 건수가 11건부터 38건까지 나왔습니다.

| 조건 | 지적 건수 |
|---|---|
| 짧은 프롬프트, 검색 차단, 배경지식만 사용 | 11건 |
| 추론 수준을 높인 경우 | 32건 |
| 참가자별 전체 범위 | 11~38건 |

같은 문서를 봐도 누가 어떤 프롬프트와 설정으로 돌렸는지에 따라 세 배 넘게 차이가 났습니다. 그래서 결과를 공유할 때는 **판정과 함께 실행 조건을 남겨야** 합니다.

## 3. 시키는 것보다 막는 것

Falsify 팀이 4주 동안 배운 것 중 첫 번째는 "시키는 것보다 막는 것이 중요하다"였습니다.

- **검색**: 검색을 막지 않으면 AI가 원논문을 찾아와 변조된 곳을 맞혔습니다. 탐지가 아니라 답 맞히기가 됩니다.
- **메모리**: 새 창에서 돌렸는데도 심은 내용이 그대로 나온 사례가 있었습니다. 과거 대화의 기억이 측정을 오염시켰을 수 있습니다.

이렇게 정답이나 힌트가 의도하지 않은 경로로 들어오는 것을 이 글에서는 **새는 정보**라고 부르겠습니다.

| 새는 경로 | 막는 방법 |
|---|---|
| 웹 검색 | 검색 기능을 끄거나, 끌 수 없으면 지시문에 금지하고 실제 사용 여부를 기록 |
| 메모리·개인화 | 설정에서 끄거나 임시 채팅 사용, 확인할 수 없으면 '확인 불가'로 기록 |
| 같은 채팅 이어 쓰기 | 회차마다 새 채팅 |
| 파일 이름·제목 | '정답표.md', '변조본_결함3개.pdf'처럼 힌트가 되는 이름 피하기 |
| 프롬프트 속 힌트 | "결함이 3개 있다", "숫자를 잘 봐라" 같은 문장 빼기 |

지시문에 "검색하지 마"라고 적는 것만으로 검색이 꺼지는 것은 아닙니다. 하네스 글에서처럼 **도구를 쓸 수 있었는지와 실제로 썼는지를 나눠 기록**하세요.

## 준비물과 이번에 만들 것

- ChatGPT 또는 Claude 계정 (메모리·검색 설정 화면을 열 수 있으면 더 좋습니다)
- 메모장이나 Markdown 편집기
- 기록표

이번 목표는 **같은 사례를 5번 실행해 일치율을 재고, 조건 하나만 바꿔 다시 재는 것**입니다.

## STEP 1. 반복 횟수와 기록 단위를 정합니다

```
반복 단위: 사례 1개 × 새 채팅 1개 = 1회
반복 횟수: 조건마다 5회
기록: 판정, 근거 인용, 원응답 전문, 실행 시각
```

5회는 연습을 위한 숫자입니다. 5번으로 모델의 일치율을 말할 수는 없습니다. 흔들리는지, 얼마나 흔들리는지 감을 잡는 정도로 씁니다.

## STEP 2. 실행 환경 점검표를 먼저 채웁니다

실행 전에 아래를 확인해 기록표 위에 적어 두세요.

```
제품·모델: 화면에 보이는 이름 그대로 (모르면 '확인 불가')
추론 수준·모드: 선택한 값 또는 '기본값'
메모리·개인화: 켜짐 / 꺼짐 / 확인 불가
웹 검색: 켜짐 / 꺼짐 / 끌 수 없음
임시 채팅 사용: 예 / 아니요
첨부 파일: 없음 / 파일명
```

설정 이름과 위치는 제품마다 다르고 자주 바뀝니다. 찾을 수 없으면 추측하지 말고 '확인 불가'로 적습니다. 이것도 결과를 해석할 때 필요한 정보입니다.

## STEP 3. 흔들리기 쉬운 사례를 고릅니다

공통 예제 "10명 전원 제공 vs 8명 제공·2명 보류"는 판정이 분명해서 잘 흔들리지 않을 수 있습니다. 그래서 경계에 있는 사례를 하나 더 준비합니다.

```
사례 ID: R01
주장: 계획한 10명 전원에게 결과를 제공했다.
근거 E01: 계획한 10명 중 8명에게 결과를 제공했고 2명은 보류했다.
```

```
사례 ID: R02
주장: 대부분의 대상자에게 결과를 제공해 사업 목표를 달성했다.
근거 E01: 계획한 10명 중 8명에게 결과를 제공했고 2명은 보류했다.
```

R02에서 "대부분"은 근거와 맞지만, "사업 목표를 달성했다"는 근거에 목표가 없어서 판단할 수 없습니다. 기대 판정은 **확인 필요**입니다. 문장 일부만 보면 '맞음', 전체를 엄격하게 보면 '아님'으로 갈 수 있어 흔들림을 보기 좋습니다.

> 기대 판정은 설명용이며 실제 모델 실행 결과가 아닙니다. 기대 판정표는 AI 입력과 분리해 보관하세요.

## STEP 4. 같은 사례를 새 채팅 5개에서 실행합니다

지시문은 하네스 글 STEP 2의 검토 도우미 지시를 그대로 씁니다. 회차마다 새 채팅을 열고 지시문과 사례를 붙여 넣습니다.

| 회차 | 사례 | 조건 | 판정 | 인용한 근거 | 원응답 위치 |
|---|---|---|---|---|---|
| 1 | R02 | 기본 | | | |
| 2 | R02 | 기본 | | | |
| 3 | R02 | 기본 | | | |
| 4 | R02 | 기본 | | | |
| 5 | R02 | 기본 | | | |

같은 채팅에서 "다시 해줘"를 누르는 것과 새 채팅을 여는 것은 다릅니다. 이번에는 새 채팅으로 통일합니다.

## STEP 5. 일치율을 셉니다

5회 중 가장 많이 나온 판정의 비율을 적습니다.

```
R02 기본 조건: 맞음 ?회 / 아님 ?회 / 확인 필요 ?회
가장 많이 나온 판정: ____ (5회 중 ?회)
```

판정만 세지 말고 **인용한 근거가 같았는지**도 보세요. 판정이 같아도 근거가 회차마다 다르면 안정적이라고 보기 어렵습니다. 스킬 글에서 "판정이 맞아도 근거를 잘못 인용했다면 제대로 된 결과가 아니다"라고 한 것과 같습니다.

## STEP 6. 조건 하나만 바꿔 다시 5회 실행합니다

이번에는 지시문에 한 줄만 추가합니다.

```
판정하기 전에, 주장을 부분으로 나누고 각 부분에 대응하는 근거 문장을 먼저 인용하라.
근거가 없는 부분이 하나라도 있으면 그 부분을 따로 표시하라.
```

나머지 조건(제품, 설정, 사례)은 그대로 두고 5회 실행합니다.

| 조건 | 가장 많이 나온 판정 | 일치 횟수 | 메모 |
|---|---|---|---|
| 기본 | | /5 | |
| 근거 먼저 인용 | | /5 | |

두 조건의 차이가 보여도 "이 문장이 흔들림을 줄였다"고 단정하지는 마세요. 5회씩으로는 우연일 수 있습니다. 다른 사례로 다시 확인할 거리로 남깁니다.

## STEP 7. (선택) 새는 정보를 직접 확인해 봅니다

메모리 기능을 켜고 끌 수 있는 경우에만 해 보세요.

1. 메모리가 켜진 상태에서 한 채팅에 "R02의 정답은 '아님'이야. 기억해 둬."라고 입력합니다.
2. 새 채팅을 열어 R02를 평소처럼 검토시킵니다.
3. 답에 앞 채팅의 내용이 영향을 준 흔적이 있는지 기록합니다.
4. **실습이 끝나면 저장된 메모리를 삭제**하고 설정을 원래대로 돌립니다.

흔적이 없었다고 해서 메모리가 영향을 주지 않는다고 결론 내릴 수는 없습니다. 반대로 흔적이 있었다면, 앞으로의 측정은 메모리를 끈 상태나 임시 채팅에서 해야 한다는 근거가 됩니다. Falsify 팀도 다음 단계로 메모리를 끄고 같은 자료를 다시 돌려 볼 계획입니다.

## STEP 8. 판정이 갈리면 결론을 줄입니다

5회 중 판정이 갈렸다면 어떻게 할까요?

| 상황 | 처리 |
|---|---|
| 5회 모두 같은 판정, 같은 근거 | 그 판정을 기록하되 회차 수를 함께 적음 |
| 판정은 같지만 근거가 다름 | 사람이 근거를 확인한 뒤 기록 |
| 판정이 갈림 | '확인 필요'로 두고 사람이 검토 |

여러 번 돌려 다수결로 정하면 되지 않을까 싶지만, 다수결도 같은 쪽으로 틀릴 수 있습니다. 멀티에이전트 글에서 "여러 AI가 모두 맞다고 했다는 것이 사실의 증거는 아니다"라고 한 것과 같습니다. Falsify 팀도 다수결로 볼지, 갈린 항목만 사람이 볼지 아직 정하지 않았습니다. 정해진 답이 없는 문제이니, 내가 어떤 규칙을 썼는지 기록에 남기는 것이 우선입니다.

## 자주 헷갈리는 질문

**몇 번 돌려야 충분한가요?**
정해진 숫자는 없습니다. 이 글의 5회는 흔들림을 눈으로 보기 위한 연습용입니다. 결과를 외부에 공유할 때는 몇 번 돌렸는지와 그중 몇 번 같았는지를 함께 적으세요.

**새 채팅이면 완전히 초기화되나요?**
그렇지 않을 수 있습니다. 하네스 글에서도 새 채팅이 문맥 분리에 도움이 될 뿐 완전한 초기화를 보장하지 않는다고 적었습니다. 메모리·개인화 설정과 함께 기록하세요.

**흔들리는 모델은 쓰면 안 되나요?**
흔들림 자체보다 흔들림을 모르고 한 번의 결과를 믿는 것이 문제입니다. 중요한 판단일수록 반복 결과와 갈린 항목을 사람이 보는 절차를 두세요.

## Falsify 실습에서는 이렇게 써보세요

- 탐지 결과를 올릴 때 **실행 환경 점검표**를 함께 남겨 주세요. 11건과 38건의 차이를 설명하려면 이 기록이 필요합니다.
- 검색은 꺼 두고, 끌 수 없으면 실제로 검색했는지를 기록하세요.
- 같은 변조본을 2회 이상 돌려 판정이 갈린 지적을 따로 표시해 주세요.

- [ ] 실행 전에 제품·메모리·검색 설정을 기록했는가 (모르면 '확인 불가')
- [ ] 회차마다 새 채팅을 썼는가

## 마무리

한 번의 답은 하나의 표본입니다. 중요한 판정일수록 **같은 질문을 한 번 더** 물어보고, 그때 무엇이 섞여 들어왔을지 함께 적어 두세요.

다음 글에서는 시선을 AI에서 우리 쪽으로 돌립니다. AI의 판정이 정답표와 다를 때, 틀린 것이 AI가 아니라 정답표일 수도 있습니다. 직접 반복해 보면서 예상보다 많이 흔들렸거나 의외로 안정적이었던 사례가 있다면 공유해 주세요.
