## 어떤 문제인가요?

Falsify는 **교육용으로 만든 가상의 논문에서, 주장과 실제 근거가 맞는지 확인하는 실습**입니다.

논문만 읽고 이상한 문장을 찾는 데서 끝나지 않습니다. 코드, 데이터, 실험 결과, 번역 전 국문 원고, Git 이력까지 살펴보며 “이 말이 정말 이 결과에서 나올 수 있나?”를 확인합니다.

그렇다고 의심스러운 부분을 전부 오류라고 하면 될까요? 정상적인 설명, 낯설지만 실제로 쓰이는 전문용어, 사소한 오타, 솔직하게 적힌 한계도 함께 들어 있습니다. **틀린 것은 근거로 짚고, 맞는 것은 맞다고 판단하는 것**이 이번 문제의 핵심입니다.

실제 환자 자료나 임상 연구가 아니라 합성 데이터로 만든 교육용 허구 연구이며, 현재는 여러분의 피드백으로 다듬어가는 **파일럿 후보판**입니다.

## 왜 만들었나요?

AI에게 논문을 검토해 달라고 하면 그럴듯한 답변을 빠르게 받을 수 있습니다. 하지만 그 답변이 실제 파일을 확인한 결과인지, 정상적인 내용까지 잘못 지적한 것은 아닌지, 수정안이 새로운 오류를 만들지는 않는지도 살펴봐야 합니다.

그래서 단순히 “오류를 찾아줘”에서 한 걸음 더 나아가, **위치를 찾고 → 근거를 대조하고 → 이유를 설명하고 → 최소한으로 고치는 과정**을 직접 경험할 수 있는 문제를 만들어보고 싶었습니다.

## 어떻게 만들었나요?

Gemini, Claude, GPT의 역할을 나누어 정상 연구 명세와 국문 원고, 실제 실행 코드와 결과, 영문 원고와 검토 자료를 만들었습니다. 먼저 정상 기준을 만든 다음 정해진 부분에 의도적인 오류를 넣고, 원고와 실험 자료를 대조할 수 있도록 구성했습니다.

이 과정에서 중요한 것은 오류를 무조건 없애는 일이 아니었습니다. **문제로 넣은 오류와 제작 중 생긴 실수를 구분하는 일**이었습니다. 정상 부분을 지키면서, 참가자가 공개된 근거로 판단할 수 있는지를 계속 확인했습니다.

처음이라면 논문의 주장 하나만 골라보세요. ChatGPT나 Claude와 함께 검토해도 좋습니다. 다만 AI의 답을 그대로 정답으로 삼기보다, **어느 파일의 어떤 값이 그 판단을 뒷받침하는지** 한 번 더 확인해 주세요.

기록은 다음 다섯 가지만 적어도 좋습니다.

1. 확인한 문장이나 주장
2. 내 판단: 문제없음 / 수정 필요 / 판단 보류
3. 근거가 있는 파일과 위치
4. 그렇게 판단한 이유
5. 필요한 최소 수정 또는 추가 확인 사항

아직 근거를 찾지 못했다면 “모르겠다” 또는 “보류”라고 적는 것도 중요한 검토 결과입니다.

## 정답과 해설은 어디서 보나요?

직접 검토한 뒤 비교해보고 싶다면 **[쉬운 정답 풀이 · Google Slides](https://docs.google.com/presentation/d/1P09S2zXM-tA635aXzYhgcVQouY0l15mUO-E-5NQPc-g/edit)**를 참고해 주세요.

해설에는 **논문 원문, 해당 위치, 쉬운 설명, 확인 근거, 판정 이유와 최소 수정안**을 함께 담았습니다. 단순한 O/X 목록보다 “왜 그렇게 판단하는가?”를 이해할 수 있도록 구성했습니다.

정답 자료는 현재 진행자에게 제한 공유되어 있어, 링크 접근이 안 되면 저나 진행자에게 열람을 요청해 주세요. 또한 정답 기준도 최종 동결 전 후보이므로, 해설과 다른 근거를 발견하시면 함께 알려주세요!
